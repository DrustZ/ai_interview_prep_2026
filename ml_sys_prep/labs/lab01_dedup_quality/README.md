## 四个实测结论

### A. MinHash 确实在估计 Jaccard

128 个置换下，估计值与真值误差在 ±0.04 量级。签名越长越准——这就是**精度 vs 内存**的权衡，也是面试要说的那句「MinHash 用固定长度签名换掉了 O(|A∪B|) 的集合运算」。

### B. LSH 的阈值是可以在白板上算出来的

一对文档在某个 band 上完全相同的概率是 `s^r`，至少命中一个 band 是 `1 - (1 - s^r)^b`，拐点约在 **`(1/b)^(1/r)`**。实测：

```
(bands,rows)   阈值     命中概率 @ s=0.4 / 0.6 / 0.8
(32, 4)        0.420    0.56   0.99   1.00      <- 松：召回高，候选多，复核贵
(16, 8)        0.707    0.01   0.24   0.95
( 8,16)        0.878    0.00   0.00   0.20      <- 紧：漏掉中度相似
```

**能写出这个式子并解释 b/r 的方向，就已经超过大部分候选人。**

### C. 过度去重删的是信息，不是冗余（本 lab 的题眼）

```
threshold=0.85   保留 7/7   转载没去掉，太松
threshold=0.70   保留 6/7   drop art_reposted (J=0.722)          <- 刚好
threshold=0.50   保留 4/7   drop prod_b (J=0.619)                <- 删错了
```

`prod_a` / `prod_b` 是两个商品页：**样板文字一字不差，规格完全不同**（X100 12V 340g 铝壳 vs X200 24V 620g 钢壳）。Jaccard 0.62 纯粹来自样板。阈值压到 0.5，删掉的是产品规格这类**长尾结构化事实**。

商品页、API 文档、财报模板、法条都是这个形态——它们恰恰是稀缺的事实来源。这就是 FineWeb 报告里「全局去重反而变差」的直觉：跨快照全局去重会把高质量的重复内容也删光。

### D. 质量分类器学到的是文体和长度，不是信息价值

用「百科式正式文本」当正样本、「导航垃圾页」当负样本训出来的分类器：

```
百科式(与正样本同分布)         0.986
导航垃圾页                    0.000    <- 这部分它做对了
口语但有实质内容的技术问答      0.976
正式但空洞的营销稿             0.996    <- 排在有实质内容的前面
极短但完全正确的事实           0.635    <- 被长度特征压低
```

它认垃圾页是对的，但**排序反了**：空洞的营销稿 > 有实质的技术问答。因为正样本全是百科式长文本，它学到的是文体。

面试必答两句：
1. **quality classifier 的正样本选择本身就是数据决策**，要说得出正样本从哪来——FineWeb-Edu 用 Llama-3-70B 给网页打 0–5 的教育性分数再训分类器；DCLM 用 OpenHermes-2.5 + ELI5 当正例训 fastText。
2. **过滤器好不好只能用固定算力的下游训练 ablation 判定**，不能看分数分布好不好看。见 [07 §十三](../../07_pretraining_data.md)。

## 追问预演

- **「exact / near / semantic 三层怎么分工？」** exact 用哈希去完全相同；near 用 MinHash+LSH 去转载和改写；semantic 用 embedding 只做**高风险切片**（benchmark 污染、合成数据、已知联合发稿），不做全库默认删除——语义相似不等于重复，容易删掉独立观点。见 07 §6.4。
- **「粒度选哪层？」** 段落级去 boilerplate/页脚、文档级去转载镜像、仓库级去 fork/vendor、快照级去重复抓取。不同粒度解决不同问题，不是二选一。
- **「重复的那份保留哪个？」** 不能随机留。按来源权威度、正文完整度、抓取时间、样板占比打分选 canonical。见 07 §6.5。
- **「LSH 之后还要精确复核吗？」** 要。LSH 只负责生成**候选**，判定必须回到真 Jaccard——本 lab 的 `dedup()` 就是这么写的。省掉这步会误删。
