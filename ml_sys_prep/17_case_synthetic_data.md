## 0. 90 秒开场（建议背下来）⭐⭐⭐

> 合成数据不是一个任务，是五个不同的任务共用一个名字。我先问要解决的是哪一个：总量不足、长尾覆盖、隐私替代、标注成本、还是难度控制。这五个目的的验收标准完全不同——补长尾的合成数据**故意不匹配真实分布**，隐私替代的合成数据**必须匹配**，两者的设计几乎相反。
>
> 无论哪一种，成功的定义只有一个：**在固定算力、固定其他变量的条件下，加了这批数据的模型在纯真实的 held-out 集上更好**。生成端的自评分、judge 平均分、"看起来很像真的"，都不是证据——它们只说明 generator 和 judge 有共同的偏好。
>
> 系统上我会做四段：**seed 采集 → 多阶段生成 → 三级质量漏斗（规则 / 程序或模型校验 / 人工抽检）→ 混合比例与代际治理**。真正决定成败的是后两段：漏斗决定单位有效样本的成本，代际治理决定这套系统能不能连续跑三个季度而不退化。
>
> 最后我会明确一条红线：**真实的 held-out eval 集里绝不能有合成数据**，以及**每条样本必须带 provenance**（generator、checkpoint、prompt 版本、seed 来源、通过了哪几级闸门）。没有 provenance，出了问题无法回滚，也无法回答"这次涨点是数据带来的还是配比带来的"。

## 1. 先问清楚：合成数据是五个任务 ⭐⭐⭐

### 1.1 七个澄清问题（每个都改变设计）

| # | 问题 | 答案会改变什么 |
|---|---|---|
| 1 | **目的是哪一个？**（总量 / 长尾 / 隐私 / 标注成本 / 难度控制） | 决定"是否需要匹配真实分布"这一条根本约束，见 §1.2。答错这题后面全错 |
| 2 | **有没有 verifier？**（可执行、可判定、可对答案） | 有 verifier → 生成可以放开、筛选可以自动、reward 可以硬。没有 → 全部退化为 judge + 人评，成本高一个量级，见 §4 |
| 3 | **数据用在哪一段训练？**（CPT / SFT / preference / RL / eval） | RL 要的是**难度落在梯度区间**的题（§5）；SFT 要的是**正确且风格一致**的示范；eval 要的是**绝不能被训练见过**的样本。同一批数据不能三用 |
| 4 | **teacher 从哪来、许可如何？** | 用商业 API 的输出训自己的模型，很多服务条款是禁止的；用开源权重模型（Nemotron-4 340B 就明确以宽松许可发布、鼓励用于合成数据）则没这个问题。这是**法务约束不是技术约束**，但面试里主动提会加分 |
| 5 | **种子数据（seed）有多少、有多脏？** | 多样性的上限来自 seed，不来自 prompt（§6.2）。只有 200 条 seed 就想造 50 万条多样样本，答案是"造不出来，先去扩 seed" |
| 6 | **真实数据的边际成本是多少？** | 如果标一条真实数据 $0.5，合成 + 筛选一条 $0.4 且质量更差，那这个项目就不该做（§10） |
| 7 | **迭代节奏与代际？**（一次性交付 / 每周再生成 / 用自己训出的模型再生成） | 决定要不要建代际治理（§7）。一次性生成不会坍塌；连续三代自产自销会 |

补充两个"如果时间够就问"的：**目标语言/领域的分布**（低资源语言的 generator 本身就弱）、**能否接触真实用户数据**（决定 §9 隐私路径）。

### 1.2 五种目的 → 五套设计（这张表是本题的骨架）

| 目的 | 是否要匹配真实分布 | 主评估 | 主要风险 | 合适范式 |
|---|---|---|---|---|
| **总量不足**（token 不够） | 大致匹配 | 下游 loss / 能力 benchmark，matched-compute | 信息密度低、复读、坍塌 | 真实文本改写（rephrase / backtranslation）、教科书式生成 |
| **长尾覆盖** | **故意不匹配**（就是要过采样稀有格） | 目标 slice 上的错误率下降，且头部不退化 | 生成的"长尾"是想象出来的，不是真实长尾 | 模板 + 组合枚举、从真实错误案例反推、evol-instruct 加约束 |
| **隐私替代** | **必须严格匹配** | TSTR（train-on-synthetic, test-on-real）对比 TRTR；同时测泄漏 | 泄漏原文；或为了隐私把分布抹平到没用 | DP 训练的 generator + 采样；结构化数据的条件生成 |
| **标注成本** | 匹配输入分布，标签要准 | 与人标金标的一致率 + 下游提升 | teacher 的系统性错误被固化 | 蒸馏、rejection sampling、weak supervision 组合 |
| **难度控制**（RL/curriculum） | 无所谓分布，只在乎**可解率落区间** | RL 训练的梯度信号占比、上分速度 | 全对/全错的题占满 batch，白烧算力 | verifier + 在线可解率探测（§5） |

**高分句**：这五个目的对"和真实分布的差距"要求是相反的。补长尾时我**要**分布偏移——那正是我付钱买的东西；做隐私替代时同样的偏移就是缺陷。所以我不会一上来报一个"分布相似度"指标，我会先问目的，再决定这个指标是往 0 优化还是往目标 slice 上定向放大。

## 2. 指标先于方案：怎么算成功 ⭐⭐⭐

### 2.1 唯一有效的证据

```text
固定：模型架构、tokenizer、优化器、总训练 token / FLOPs、eval suite 版本、随机种子（最好多个）
变量：只有"是否加入这批合成数据"（或配比 x%）
结论：在【纯真实】的 held-out / prospective 集上的下游指标差异
```

这就是 [07 §13.2](07_pretraining_data.md) 那套 ablation 规范在合成数据上的落地。**没有 matched-compute ablation 的合成数据结论都是猜。**

### 2.2 不能用的指标（面试里主动列出来）

| 常见但错的指标 | 为什么错 |
|---|---|
| **generator 自评分 / "这条题质量 9/10"** | 生成和评分是同一个模型（或同族），偏好高度相关。它在给自己打分 |
| **LLM judge 的平均分上升** | judge 偏好长度、格式、礼貌、自身写作风格。分数升了可能只是学会了讨好 judge。judge 只能做 triage 和排序，不能当 ground truth（[07 §13.3](07_pretraining_data.md)） |
| **人评"看起来像真人写的"** | 真实性 ≠ 有用性。最像真实分布的合成数据往往信息增益最低（它只是复述你已有的东西） |
| **多样性分数（distinct-n / self-BLEU）单看** | 把温度调到 2.0 可以让任何多样性指标变好，同时让质量崩掉。多样性必须**在质量闸门之后**测 |
| **生成条数 / token 数** | 这是产能不是价值。1000 万条全对全错的题在 RL 里价值是 0（§5） |
| **验证集 loss 下降** | 如果验证集也含合成数据，这就是自证。真实 held-out 必须 100% 真实 |

### 2.3 验收合同（acceptance contract，开工前写死）

在生成一条数据之前，先把这份东西写下来并让对方签字：

```text
1. 主指标：目标域真实 held-out 上的 <具体指标>，相对 baseline 提升 ≥ X%（给绝对值和置信区间）
2. Guardrail：通用能力回归 ≤ Y%；目标 slice 提升不能以头部 slice 退化换取
3. 污染：与所有 eval 集的 n-gram / embedding 近重复率 ≤ Z（且报告检测方法，不承诺"零污染"）
4. 多样性下限：taxonomy 网格覆盖率 ≥ A%，每格最少 N 条；embedding 聚类熵 ≥ B
5. Provenance：每条样本可追溯 generator / checkpoint / prompt 版本 / seed / 闸门通过记录
6. 成本上限：每条【通过闸门】的样本成本 ≤ $C（注意分母，见 §11）
7. 失败判据：ablation 不显著就是不显著，写进报告，不补测到显著为止
```

第 7 条来自我在 Anthropic take-home 里的做法：两个被数据推翻的先验（refuted prior）我如实写进了报告。**主动说"我会预先定义失败判据"，比任何漂亮设计都更能证明是个能被信任的数据人。**

## 3. 生成范式对比 ⭐⭐⭐

### 3.1 六种范式的取舍表

| 范式 | 机制 | 多样性来源 | 单条成本 | 典型失效 | 什么时候选 |
|---|---|---|---|---|---|
| **模板 / 程序化** | 语法、槽位填充、程序合成（如自动出题、代码变异） | 组合空间（可穷举、可控） | 近似 0 | 表面变化大、语义变化小；模型很快学到模板指纹 | 需要**精确控制**某个因子（数值范围、代码结构、噪声类型）；需要 100% 正确标签 |
| **LLM zero/few-shot 直接生成** | 写个 prompt 让模型造 | prompt + 采样噪声（**很弱**） | 低 | 模式坍塌：几千条里就那几种句式和主题 | 只适合快速 smoke test，不适合规模化 |
| **Self-Instruct** | 少量种子任务 → 模型自举生成新指令 → 过滤 → 回填输入输出 | 种子池 + 迭代扩池 | 低 | 指令越滚越像；需要显式相似度过滤（原论文对已有指令 ROUGE-L > 0.7 就丢弃） | 从 0 到 1 造指令数据；Alpaca 用它以约 500 美元造出 52K 条 |
| **Evol-Instruct** | 对已有指令做定向"进化"：加约束、加推理步数、具体化、复杂化输入（in-depth）+ 换主题（in-breadth），并淘汰进化失败的 | 进化算子的设计 | 中 | 进化过头变成不可解或题意矛盾；**必须配一个"进化失败检测"** | 有一批简单指令，想造难题；难度阶梯需要连续可控 |
| **从真实数据反推** | 拿真实文档反向生成问题/指令（instruction backtranslation）；或把网页按风格改写（rephrase，如 WRAP 报告约 3× 预训练加速） | **真实语料的多样性**（最强） | 中 | 反推出的问题与文档不自洽；改写引入事实漂移 | 有大量无标注真实文本时的**首选**。事实性来自真实文本，表达多样性来自改写 |
| **蒸馏 / rejection sampling** | 强 teacher 产多个候选 → verifier 或 judge 选 → 只留通过的（STaR / RFT 家族） | teacher 的采样多样性 | 高 | teacher 不会的能力蒸不出来；teacher 的系统性错误被放大 | 有可验证信号时性价比最高；Nemotron-4 340B 报告其对齐数据 98% 以上为合成 |

### 3.2 三条能当"判断力"讲的结论

**结论 A：多样性来自 seed，不来自 prompt。** 在 prompt 里写"请生成多样的题目"几乎无效。HuggingFace 的 Cosmopedia（25B token 合成教科书语料）复盘的核心经验就是：多样性靠**种子的多样性**——从真实网页聚出的主题、不同的受众设定、不同的文体，而不是靠让模型自己发挥。这条在面试里非常好用，因为它把"多样性"从玄学变成了可工程化的东西：**多样性是采样设计问题，不是 prompt 工程问题**。

**结论 B：范式要混着用，而且要分阶段。** 我在 Reflection 做 math/STEM 数据的真实做法是一条**多阶段 LLM 流水线**，而不是一次生成：

```text
seed：开源数据集 + 原始文本（教材 / 论坛 / Stack Exchange / 竞赛题）
  → stage 1  question rewriting：补全缺失前提、去掉图片依赖、统一表述
  → stage 2  QA 转换：把不可验证的题改写成可验证形式（唯一数值答案 / 可判定命题）
  → stage 3  answer rewriting：规范解题格式，剥离与答案无关的闲聊
  → stage 4  质量特征打分（自包含 / 无矛盾 / 假设充分，见 §4.2）
  → stage 5  难度探测与筛选（§5）
  → 出库（带 provenance）
```

**"把不可验证的题转成可验证的题"是这条流水线里价值最高的一步**——它把下游从"只能靠 judge"变成"可以靠程序"，直接决定了 §4 漏斗的成本结构。面试里讲这一步比讲任何 prompt 技巧都有分量。

**结论 C：合成数据最好的用途往往是"改写"而不是"凭空造"。** 凭空造的东西受限于 generator 的知识；改写真实文本时，事实来自真实语料，模型只负责换表达。前者容易幻觉，后者不容易。phi 系列那类"教科书质量"合成语料之所以有效，也是因为它是**在真实知识上做教学化重组**，不是无中生有。

## 4. 质量闸门：三级漏斗 ⭐⭐⭐

一个 LLM judge 打分不是质量闸门。真正的闸门是**成本递增、覆盖递减**的多级漏斗，每一级只做它擅长的事。

### 4.1 漏斗结构与预期通过率

| 级 | 手段 | 抓什么 | 抓不到什么 | 相对成本 | 典型通过率 |
|---|---|---|---|---|---|
| **L0 规则** | 长度、语言 ID、格式/schema、必需字段、答案可解析、重复 n-gram、明显截断、禁用词 | 垃圾和管道故障 | 一切语义问题 | ~0 | 70–95% |
| **L1 程序 / verifier** | 执行代码跑测试、数值答案比对、单位与量纲检查、约束求解、schema 一致性、**与 seed 文档的一致性检查** | 硬错误（答案错、代码不跑、违反约束） | 题目本身不合理（有答案但题烂） | 低 | 40–80%（可验证域） |
| **L2 模型校验** | LLM/LRM judge 按 rubric 打**离散标签**（不是 1–10 分），多维度：自包含性、矛盾性、假设完备性、与 seed 的相关性 | 语义层缺陷 | 自己也会错、也不一致（§4.3） | 中（可占总成本 20–40%） | 50–85% |
| **L3 人工抽检** | 分层抽样 + 领域专家；**不是全量标注**，是校准前三级 | 前三级的系统性盲区 | 规模 | 高 | —（这是测量，不是过滤） |

**关键设计原则：越便宜的闸门放越前面，且每一级都要记录被丢弃的原因。** 丢弃原因的分布本身是最有价值的监控信号（§4.4）。

**L3 抽样怎么抽（面试常追问）**：不要均匀抽。按**闸门判定分层**抽——L2 判"通过"的抽一部分、判"拒绝"的抽一部分、判在阈值附近的重点抽。这样才能同时估计 judge 的 precision 和 recall。只抽通过的样本，你永远发现不了 judge 把好数据误杀了多少。

### 4.2 质量特征清单（可直接背，来自我实际用过的）

对每条生成的题目，我打的是这几个**二元/三值标签**而不是一个总分：

| 特征 | 判什么 | 为什么它单独成一维 |
|---|---|---|
| **是否自包含** | 题目脱离原始上下文后还能不能解（有没有"如上图"、"根据上一题"、指代不明的 it/they） | 这是网页/论坛来源数据最常见的坏法。不自包含的题在训练时会教模型瞎猜 |
| **是否含矛盾信息** | 条件之间是否冲突（"三角形三边 1,2,5"） | 矛盾题会有"答案"，verifier 也可能给过，但它教的是错的 |
| **解题假设是否给足** | 缺失的必要前提（未给定单位、未说明定义域、隐含约定） | 假设不足的题会让强模型和弱模型给出不同但都"合理"的答案 → reward 噪声 |
| **答案是否唯一可判定** | 是否存在多解 / 表述等价但字符串不同 | 决定这条题能不能进 RL |
| **与 seed 的一致性** | 改写后是否偏离了原文事实 | 抓改写型 pipeline 特有的事实漂移 |

**为什么用离散标签而不是 1–10 分**：judge 给的连续分数在不同题目上不可比（§4.3），而"是否自包含"这种问题有明确定义，一致性高得多。**把主观打分拆成一组客观判定，是提升 judge 可靠性最有效的一招。**

### 4.3 LRM-as-judge 的一致性问题（我真踩过）

我在做数据筛选时遇到的具体问题是：**同一条评判标准，judge 在不同题目上判得不一致**。同一个"是否自包含"的要求，在几何题上判得严，在应用题上判得松。

诊断和缓解手段（按性价比排序）：

| 手段 | 做法 | 效果 |
|---|---|---|
| **把 judge 一致性本身当指标** | 同一批样本重复判 3 次测自一致；不同 judge 之间测互一致（Cohen's κ / Krippendorff α） | 先量化，不量化就没法改。**κ < 0.4 的维度直接不要用** |
| **rubric 锚点样例** | 每个标签给 2–3 条正例 + 2–3 条边界反例，放进 prompt 前缀（顺便吃满 prompt cache） | 最见效的一招 |
| **拆维度 + 二元化** | 见 §4.2 | 大幅提升 |
| **成对比较代替绝对打分** | 判"A 和 B 哪个更自包含"而不是"A 打几分" | 一致性更好，但成本 O(n²)，只用于校准子集 |
| **人工锚点集** | 固定一套 200 条人标样本，每次换 judge / 换 prompt / 换模型版本都重跑，报和人标的一致率 | **这是 judge 的回归测试**。没有它，换个模型版本你的数据质量就静默漂移了 |

**高分句**：judge 不是 ground truth，是一个**需要被校准和被回归测试的模型组件**。我会给 judge 建版本号、建固定的人工锚点集，并把 judge 与人标的一致率作为一个必须监控的生产指标——因为 judge 一旦漂移，整条数据管线的质量会静默退化，而下游要几周后才发现。

### 4.4 漏斗监控：通过率是最灵敏的告警

每一级的通过率、以及被拒原因的分布，都要按天画出来（对应 [07 §15.2](07_pretraining_data.md) 的 funnel dashboard）。

- L0 通过率突降 → 上游 seed 来源变了，或者 generator 输出格式变了（最常见：换了模型版本）
- L1 通过率突升 → 警惕，可能是 verifier 坏了在放水，不是质量变好了
- L2 通过率突变但 L1 不变 → judge 漂移，去查 judge 的锚点集
- **各级通过率都正常但下游不涨** → 闸门在筛"合法"而不是在筛"有用"，回到 §2

## 5. 难度控制与梯度信号：合成数据最被低估的一节 ⭐⭐⭐

这一节是我最有真实素材、也最能拉开差距的地方。

### 5.1 核心洞察：难度不是题目的属性，是（题目, 模型）的函数

一道题"难不难"取决于当前 policy 的可解率。所以：

- **离线标注的难度标签会过期**。你标的"难题"训了两周之后对新 checkpoint 可能是送分题。
- **难度筛选必须在线做，且阈值要随模型漂移**。

### 5.2 我实际做的：自适应难度阈值 + 小批量探测

```text
对每道候选题：
  1) 先用当前 policy 跑 16 条 rollout（小批量探测，用较短的 max_tokens）
  2) 估计可解率 p̂
     - p̂ == 1（全对）→ 丢弃：没有梯度信号，纯烧算力
     - p̂ == 0（全错）→ 丢弃：要么太难、要么题/verifier 有问题
     - 0 < p̂ < 1     → 保留
  3) 保留的题再跑 128 条正式 rollout
筛选（探测 + judge）总共约占 12% 的算力预算
```

**为什么 12% 是可以接受的**：设探测 k_p=16、正式 k_f=128、保留率 r。若探测与正式的单条成本相同，探测开销占比 = k_p / (k_p + k_f·r)，r≈0.6 时约 17%。实际做到 ~12% 是因为探测阶段用了更短的 max_tokens 并对明显全错的题提前终止。**面试里能把这个算术当场算出来，比报一个数字有说服力得多。**

**这个思想和 DAPO 的 dynamic sampling 是一致的**——过采样 prompt，然后把准确率为 1 或 0 的 prompt 过滤掉，保证 batch 里全是有有效梯度的样本。能主动指出"我们独立做到的东西和 DAPO 是同一个思想"，既诚实又显得读过文献。

### 5.3 不同用途的难度目标（这张表能直接答追问）

| 用途 | 期望可解率 | 理由 |
|---|---|---|
| **RL / GRPO 类** | 0 < p < 1，最好在 0.2–0.8 | p=0 或 1 时组内 advantage 全为 0，梯度为 0。这是硬约束不是偏好 |
| **SFT 示范数据** | 高（p 接近 1 的题里选正确 trace） | SFT 要的是干净示范，不是挑战 |
| **Curriculum 早期** | 0.6–0.9 | 先建立格式和基本能力 |
| **Curriculum 后期** | 0.1–0.4 | 逼近能力边界 |
| **Eval 集** | 覆盖全谱且**固定不变** | eval 的难度不能随模型调，否则不可比 |

### 5.4 难度筛选的副作用（主动讲，是加分项）

1. **系统性丢掉一整类题**。如果某类题 verifier 有 bug 导致永远判错，它们会全部落在 p̂=0 被丢弃——你会**静默地**失去这一整类能力。**防御**：对被丢弃的样本按类别统计，某个类别丢弃率异常高就人工看。
2. **难度筛选会和数据分布筛选耦合**。保留下来的题在主题上可能严重偏斜（比如全是某一类代数题）。**防御**：难度筛选之后再做一次分层抽样，保证 taxonomy 覆盖（§6.4）。
3. **探测本身有方差**。16 条 rollout 估计 p 的标准误在 p=0.5 时约 0.125。所以"全对/全错"这个判据其实是在做一个**保守**的丢弃：真实 p=0.05 的题有 (0.95)^16 ≈ 44% 的概率被 16 条探测判成全错。这是可接受的（我们不缺题），但如果题很贵就要加大 k_p 或做序贯检验。**能把这个概率算出来，是真的做过这件事的标志。**

## 6. 多样性 vs 质量的张力 ⭐⭐⭐

### 6.1 温度不是多样性旋钮

| 温度 ↑ 的四个后果 | 说明 |
|---|---|
| 表面多样性 ↑ | 用词、句式变化变大 |
| **语义多样性 ↑ 得很有限** | 还是那几个主题——因为主题由 prompt/seed 决定 |
| 质量 ↓ | 事实错误、格式错误、不可解题增多 |
| **闸门通过率 ↓ → 单位有效样本成本 ↑** | 这是关键：温度调高看似免费，实际把成本推到了漏斗里 |

**结论**：温度是在"生成成本"和"筛选成本"之间做交换，不是在制造新信息。要真正提升多样性，去改 seed、改 taxonomy、改 evol 算子。

### 6.2 多样性的正确来源（按杠杆从大到小）

1. **seed 的多样性**（最大杠杆）：从真实语料聚类出主题、从真实错误日志采集失败模式、从多个来源采集。
2. **条件维度的显式笛卡尔积**：主题 × 难度 × 语言 × 受众 × 文体 × 长度 × 干扰项类型。把这些写成结构化的生成配置，而不是塞进一句 prompt。
3. **evol 算子的多样性**：不同的变换算子（加约束 / 换领域 / 加干扰信息 / 改问法）。
4. **generator 的多样性**：用 2–3 个不同家族的模型生成，能显著打散单模型的风格指纹。
5. **采样温度**（最小杠杆，且有副作用）。

### 6.3 去重：合成数据和真实数据的去重不一样

通用机制（exact hash → MinHash/LSH near-dup → embedding 语义去重）在 [07 §六](07_pretraining_data.md)，这里只讲**差异**：

| 差异点 | 说明 |
|---|---|
| **合成数据的重复是"模式重复"不是"字符串重复"** | 两条题换了人名和数字，字符串距离很大，但对模型是同一条。exact/MinHash 抓不到 |
| 因此必须做 **embedding 层的近邻去重 + 聚类去重** | 对每条新样本查 embedding 近邻，相似度超阈值就丢；或者聚类后限制每簇最大条数 |
| **还要对"骨架"去重** | 把数字、变量名、实体名归一化成占位符之后再做 exact/n-gram 去重——这一步能抓到模板化生成最典型的重复 |
| **Self-Instruct 的具体做法可以引用** | 新生成的指令与任何已有指令 ROUGE-L 相似度 > 0.7 就丢弃。一个便宜、有效、可直接说出数字的基线 |
| **必须对 seed 去重** | 合成样本和它的 seed 太像 = 没有增加信息，只是换了个说法（隐私场景下还是泄漏风险，§9） |
| **必须对所有 eval 集去重** | 合成数据是**污染的高危来源**：generator 可能记得 benchmark 题目并"重新发明"它们。exact match 不够，要做语义近重复检测（[07 §八](07_pretraining_data.md)） |

### 6.4 覆盖度怎么量（四个可落地的指标）

| 指标 | 怎么算 | 读什么 |
|---|---|---|
| **taxonomy 网格填充率** | 预先定义维度网格（主题 × 难度 × 类型），统计非空格子比例 + 每格最少条数 | 最可解释、最能驱动行动。空格子直接告诉你下一批该生成什么 |
| **相对真实数据的聚类覆盖** | 在真实数据上跑 k-means（k=200～1000），把合成数据投进去，看每簇的质量占比 | 空簇 = 真实分布里有而合成数据没覆盖的区域 |
| **新 n-gram 率** | 相对 seed 的新 n-gram 比例 | 太低 = 只是在复读 seed；太高 = 可能在胡说 |
| **self-BLEU / distinct-n** | 样本两两之间的相似度 | 便宜的模式坍塌告警。**必须在质量闸门之后算**，否则垃圾会让它虚高 |

**一句话**：我会把覆盖度做成一个**带空格告警的网格看板**，而不是一个标量分数——因为标量分数不能告诉团队下一步生成什么。

## 7. 模型坍塌（model collapse）⭐⭐⭐

### 7.1 现象与机制

反复用自己（或同代模型）生成的数据训练下一代，会发生**代际退化**。Shumailov 等人 2024 年发表在 Nature 的工作把它命名为 model collapse，并区分了两个阶段：

- **早期坍塌**：分布的**尾部先消失**。模型仍然"看起来正常"，但罕见事件、少数群体、长尾表达被逐代抹去。**这是最危险的阶段——指标可能还在涨。**
- **晚期坍塌**：方差持续收缩，输出趋于同质、趋向少数几个模式，与原始分布几乎无关。

三个误差来源：**统计近似误差**（有限采样必然丢尾部）、**函数表达力误差**（模型族表达不了真实分布）、**函数近似/优化误差**（训练本身的偏差）。三者逐代累积。

同期 Alemohammad 等人的 "Self-Consuming Generative Models Go MAD" 给出同样结论的生成模型版本：自噬循环里如果每代没有足够的**新鲜真实数据**，质量或多样性之一会逐代下降。

### 7.2 最重要的反直觉结论：replace vs accumulate

Gerstgrasser 等人 2024 的工作指出：坍塌的前提是**用合成数据替换（replace）真实数据**。如果每代是**累积（accumulate）**——真实数据保留、合成数据往上加——测试误差存在一个与代数无关的**有限上界**，坍塌不再发生。

**这条在面试里价值极高**，因为它把"模型坍塌"从一个吓人的名词变成一个**具体的工程约束**：

> 别丢真实数据。每一代训练集都必须包含全部（或固定比例的）原始真实数据，合成数据只做增量。

同时要诚实指出这不是完全定论：Dohmatob 等人的 "Strong Model Collapse" 一系的结果表明，在某些设定下**即便只掺入很小比例的合成数据也会造成可测量的退化**，且更大的模型未必更稳健。所以正确的表述是：**累积策略显著缓解坍塌，但"多少合成数据是安全的"必须由你自己的 ablation 回答，不能引用一个通用比例。**

### 7.3 四条防线（每条配一个监控指标）

| 防线 | 做法 | 监控指标 |
|---|---|---|
| **1. 真实数据锚定** | 每代训练集必须含固定比例的原始真实数据；accumulate 而不是 replace | 真实数据在训练 token 中的占比（设下限告警） |
| **2. 代际比例上限** | 给每条数据打"代际标签"（gen-0 = 真实，gen-1 = 用 gen-0 模型生成，…），限制 gen ≥ 2 数据的总占比 | 各代际的 token 占比曲线 |
| **3. 分布监控** | 每代对比：长度分布、词表覆盖、perplexity 分布（用一个**冻结的**参考模型算）、embedding 聚类熵、罕见 token 频率 | 尾部质量占比是最灵敏的早期信号 |
| **4. 外部验证锚** | 用一个**永不参与生成、永不更新**的真实 held-out 集 + 定期人评做终审 | 该集上的指标 + 人评一致率 |

**第 3 条里"用冻结的参考模型算 perplexity"这个细节很重要**：如果用当代模型自己算，坍塌的模型会觉得自己的输出困惑度很低——自证清白。

### 7.4 什么情况下坍塌风险高 / 低

| 风险 | 情形 |
|---|---|
| **低** | 有强 verifier 的可验证域（数学答案、代码测试）。因为筛选把错误挡住了，信息实际上是从 verifier 注入的，不是从模型自身循环出来的 |
| **低** | 单次一代生成，不迭代 |
| **中** | 用一个更强的外部 teacher 蒸馏（是知识转移，不是自噬），但会继承 teacher 的偏差 |
| **高** | 用自己上一代模型生成、且替换掉真实数据 |
| **高** | 开放式生成任务（创作、对话）+ 只有 judge 没有 verifier |

**高分句**：模型坍塌的本质是**信息没有新增，只是被反复重采样**。所以判断一个合成数据 pipeline 会不会坍塌，只要问一句：**这条 pipeline 里，新信息从哪里进来？** 如果答案是 verifier、真实语料、或人，就相对安全；如果答案只有"模型自己"，那就是在做分布的复印件的复印件。

### 7.5 诚实边界

> 我没有跑过跨多代自训练的长期实验——我做的是单代或两代的生成+筛选，坍塌是我按文献和分布监控在防，不是我亲自复现过的现象。我见过的是**单代内的模式坍塌**（生成几万条之后主题高度集中），那个我有直接的处理经验。

这么说比假装做过多代实验强得多，而且后半句给了真实素材。

## 8. 分布偏移：怎么量、怎么校正

### 8.1 度量工具箱

| 方法 | 做法 | 读法 | 适用 |
|---|---|---|---|
| **判别器二样本检验（C2ST）** | 训一个分类器区分真实 vs 合成，报 held-out AUC | AUC ≈ 0.5 → 不可区分；AUC 高 → **看分类器最看重的特征，那就是 artifact 清单** | **首选**。便宜、可解释、直接给出修复方向 |
| **TSTR vs TRTR** | Train-on-Synthetic-Test-on-Real 与 Train-on-Real-Test-on-Real 对比 | 差距即"合成数据的可替代性" | 隐私替代场景的**标准评估** |
| **MAUVE** | 在 embedding 空间聚类后比较两个分布的散度前沿 | 单一标量，适合做趋势监控 | 开放式文本生成 |
| **precision / recall 分解** | 生成分布落在真实分布支撑内的比例（precision）vs 真实分布被覆盖的比例（recall） | **必须分开看**：高 precision 低 recall = 只会造安全的常见样本；低 precision = 在造真实世界不存在的东西 | 想区分"质量问题"还是"覆盖问题"时 |
| **边缘分布对比** | 长度、perplexity（冻结参考模型）、词频齐夫曲线、实体分布、标签分布 | 最便宜的一层，先跑这个 | 永远先做 |

**C2ST 的用法值得展开讲**：AUC 0.95 不只是"差别大"，它还告诉你**差在哪**——去看分类器的 top feature。我见过的典型 artifact：合成样本长度分布过于集中、几乎不出现拼写错误、标点用法过于规范、总是以某几个固定短语开头、数字总是整数。**这些都是可以直接回去修 prompt 的。**

### 8.2 校正手段

| 手段 | 说明 | 代价 |
|---|---|---|
| **重要性加权** | 用 C2ST 判别器的输出算权重，在训练时给"更像真实"的合成样本更高权重 | 权重方差可能爆炸，要 clip |
| **拒绝采样对齐** | 用判别器直接拒掉最容易被识别为合成的样本 | 会降低多样性（把尾部砍掉了，可能加速坍塌） |
| **调整生成配置** | 按 C2ST 的 top feature 反向修 prompt / 采样参数 / seed 分布 | **最根本的修法，优先做这个** |
| **调整混合比例** | 不修分布，改用量。用 ablation 扫 5% / 10% / 20% / 40% | 最实用；很多时候少加一点就够了 |
| **只在缺口处补** | 不追求全局分布匹配，只在 taxonomy 网格的空格子里生成 | 目标是长尾覆盖时的**正确做法** |

### 8.3 一个必须说清楚的反直觉

**"和真实分布越接近越好"是错的**，取决于 §1.2 的目的：

- 隐私替代：越接近越好（但要防泄漏，见 §9）。
- 长尾覆盖：**故意偏离**——如果你的合成数据分布和真实分布一样，那它对长尾就毫无贡献。
- 难度控制：分布无关，只要可解率落在区间。

所以我在报告里会写"相对真实分布的偏移量"，但**不会把它当作要最小化的目标函数**，而是当作一个必须被解释的量：这个偏移是我要的吗？

## 9. 隐私与合规

### 9.1 核心原则：合成 ≠ 匿名

从真实数据训练出来的 generator，会以两种方式泄漏：

1. **逐字记忆**：训练数据里的罕见字符串（身份证号、病历号、罕见姓名组合）被原样吐出。Carlini 等人的 "Secret Sharer" 给了标准做法：**往训练数据里插入 canary（人造的罕见字符串），训练后测模型吐出它的概率（exposure）**。这是一个可以直接执行的泄漏测试。
2. **准标识符组合重识别**：单个字段都不敏感，组合起来唯一定位到一个人（邮编 + 出生日期 + 性别是经典例子）。**只做命名实体识别（NER）扫 PII 是不够的**——NER 抓不到组合泄漏。

监管侧的立场也是一致的：合成数据不会自动获得"匿名数据"的身份，判据是**能否重识别**。

### 9.2 三档隐私强度（按需选，不要一上来就上最重的）

| 档 | 做法 | 保证 | 代价 |
|---|---|---|---|
| **弱**：PII 清洗 + 人工抽检 | 规则 + NER 脱敏，抽检 | 无形式保证，只挡低垂果实 | 低 |
| **中**：清洗 + 记忆测试 + 近重复过滤 | 加 canary exposure 测试；合成样本与任何真实样本的相似度超阈值就丢 | 经验保证，可量化 | 中 |
| **强**：差分隐私 | 用 DP-SGD 微调 generator，然后采样 | **形式保证**：由于 DP 的后处理免疫性（post-processing immunity），从 DP 训练的模型采样出的任意多合成数据，都继承同一个 (ε, δ) 预算，**采样本身不额外消耗隐私预算** | 高：文本质量明显下降，ε 越小越明显；需要专门的训练基础设施 |

**"后处理免疫性"这个点在面试里很值钱**：它解释了为什么 DP 合成数据是有吸引力的——训练一次付一次隐私代价，之后想生成多少条都不再增加泄漏风险。这是 DP 合成数据相对"每次查询都加噪"的关键优势。

### 9.3 医疗场景的具体锚点

我在 Anthropic 的 take-home（医疗领域）里做过相关的东西，可以诚实地讲：那个任务是判断回复是否 grounded 在给定材料上。我做的 **claim 级 grounding grader** 在"预测医生标注的不安全回复"上 AUROC 达到 0.844，而 ROUGE 只有 0.569（约等于掷硬币），两者置信区间不重叠。**这套东西直接可以复用为合成数据的 L2 闸门**：判"这条合成回答的每个 claim 是否有来源支撑"，比判"这条回答质量好不好"可靠得多。

同一个 take-home 里我还建了 **137 对扰动测试套件**，按扰动类型分层报检出率——这个方法论对合成数据同样适用：**造一批已知有缺陷的合成样本（故意去掉前提、故意加矛盾、故意改数字），看闸门能抓住多少**。这是给质量闸门做单元测试。

### 9.4 合规红线清单

- 用第三方 API 的输出训模型 → 先看服务条款（§1.1 第 4 问）。
- 从用户数据合成 → 确认 consent 覆盖这个用途，租户隔离，保留 / 删除策略要能级联到合成产物（删了原始数据，从它衍生的合成数据怎么办？**provenance 就是为了回答这个问题**）。
- 医疗/金融领域有明确的去标识化标准（如 HIPAA 的 Safe Harbor 十八类标识符 vs expert determination 两条路径）。
- **诚实边界**：我没有做过金融/交易领域的数据，也没有承担过受监管数据的合规签字责任。涉及这块我会说"我知道要问什么问题、要建什么测试，但具体的合规判定我会拉法务和领域专家"。

## 10. 什么时候合成数据是错误的选择

主动讲这一节，是"有判断力"最直接的证明。

| 情形 | 为什么不该合成 | 该做什么 |
|---|---|---|
| **真实数据便宜且可得** | 合成 + 筛选 + 验证的总成本经常超过直接标注，而且质量更差、还多一层分布风险 | 直接买/标。先算清楚每条**通过闸门**的合成样本成本 vs 每条真实标注成本 |
| **分布极难建模** | 真实用户的行为分布、真实的对抗攻击、真实的长尾故障——你想象出来的长尾不是真实的长尾 | 采集真实流量、shadow 模式、红队 |
| **没有 verifier 且没有人评预算** | 生成能力远超筛选能力时，你只是在放大 generator 的偏差 | 先建评估，再谈生成。**评估先行**是这一题的通用答案 |
| **teacher 不具备目标能力** | 蒸馏蒸不出 teacher 没有的东西；让弱模型生成"高难度题"会得到看起来难但实际错的题 | 换 teacher，或改用 verifier 驱动的搜索（让模型多试，用 verifier 挑） |
| **要建 eval 集** | 合成 eval 会系统性地偏向和 generator 同族的模型，且极易被训练集污染 | eval 必须真实、必须冻结、必须与训练数据做污染检测 |
| **只是为了"数据量看起来多"** | 见 §2.2 | 停 |
| **已经跑了两三代自产自销** | 见 §7 | 先补真实数据，再谈生成 |

**必背句**：合成数据是**信息的重新分配**，不是信息的创造。它能把已有的信息重新包装成更适合训练的形式，能把 verifier 或真实语料里的信息注入模型，但它不能凭空产生你的系统里原本没有的知识。**问清楚"新信息从哪进来"，就能判断这个项目值不值得做。**

## 11. 成本控制与基础设施

### 11.1 成本公式（注意分母）

```text
每条【可用】样本成本
  = (生成成本 + 筛选成本 + 人工抽检摊销) / (生成条数 × 全漏斗通过率 α)
```

**分母是通过闸门的条数，不是生成条数。** 这和 [14 §10](14_case_customer_service_agent.md) 里"每次**已解决**的成本"是同一个思想：一个便宜但通过率 10% 的 pipeline，比贵一倍但通过率 60% 的 pipeline 更贵。

面试里主动说这句：**我不看每千 token 的单价，我看每条进库样本的成本。**

### 11.2 分层生成：便宜量产 + 贵模型精修

```text
Tier 1  廉价模型批量生成 N 个候选        ← 量
Tier 2  规则 + verifier 过滤（近乎免费）  ← 砍掉 40–70%
Tier 3  中档模型做 L2 judge              ← 排序 / 标注
Tier 4  贵模型只处理两类：judge 判为边界的样本、需要精修改写的样本  ← 质
Tier 5  人工只看分层抽样（几百条量级）    ← 校准
```

以 Claude 家族 2026-07 的 API 价目为锚点（$/1M token，input/output）：

| 层 | 模型 | 价格 | 在漏斗里的位置 |
|---|---|---|---|
| 廉价 | Claude Haiku 4.5 | $1 / $5 | Tier 1 量产、L0/L1 辅助判定 |
| 中档 | Claude Sonnet 5 | $3 / $15 | Tier 3 judge 主力 |
| 高档 | Claude Opus 5 | $5 / $25 | Tier 4 精修、边界仲裁 |
| 顶配 | Claude Fable 5 | $10 / $50 | 只用于难例仲裁 / 建 rubric 锚点 |

**算一笔账（假设每条候选 input 800 tok / output 1200 tok）**：

| 生成模型 | 每条候选成本 | 批处理后（-50%） |
|---|---|---|
| Haiku 4.5 | $0.0008 + $0.0060 = **$0.0068** | $0.0034 |
| Sonnet 5 | $0.0024 + $0.0180 = **$0.0204** | $0.0102 |
| Opus 5 | $0.0040 + $0.0300 = **$0.0340** | $0.0170 |

要 100 万条可用样本、全漏斗通过率 30% → 需 ~333 万条候选。
- 全用 Opus：333 万 × $0.017（批处理）≈ **$5.7 万**
- Haiku 量产 + 20% 走 Opus 精修：333万 × $0.0034 + 67万 × $0.017 ≈ $1.13 万 + $1.14 万 ≈ **$2.3 万**

**分层把成本砍到约 40%，前提是 Tier 2 的 verifier 真的能挡住 Haiku 的大部分错误**——所以分层生成的可行性完全取决于 §4 漏斗的强度。这个依赖关系要在面试里说出来。

### 11.3 三个具体的降本杠杆

| 杠杆 | 机制 | 量级 |
|---|---|---|
| **批处理 API** | 非实时任务走批处理接口 | **约 50% 折扣**（Anthropic Message Batches：单批最多 10 万请求 / 256MB，多数 1 小时内完成，上限 24 小时） |
| **Prompt caching** | 生成/评判的 prompt 前缀（系统指令 + rubric + few-shot 锚点）在成千上万次调用中完全相同 | 缓存**读**约 0.1×，缓存**写** 1.25×（5 分钟 TTL）或 2×（1 小时 TTL）。5 分钟档命中一次就回本（1.25 + 0.1 = 1.35× < 2×）；1 小时档要两次（2 + 0.2 = 2.2× < 3×） |
| **分层 + 早停** | 见 11.2；以及在 Tier 1 就用短 max_tokens 探测（§5.2） | 结构性，通常是最大的一块 |

**Prompt caching 在合成数据场景是天然契合的**——同一个 rubric 要评十万条样本，前缀完全固定。要注意的坑：**任何一个字节的变动都会让缓存失效**，所以 prompt 里不能有时间戳、随机 ID、未排序的 JSON；变动的内容（待评样本）必须放在最后。

自建 vs API：真正到千万条量级，主流做法是用自己的 GPU 跑开源权重模型；API 价目的作用是**给"买还是自建"提供一个可比的锚**。这句话要说，否则显得只会调 API。

### 11.4 批量推理基础设施（我的真实素材）

合成数据的算力特征是：**吞吐敏感、延迟不敏感、可中断**。这和在线 serving 完全相反，所以它天然适合跑在抢占式 / 共享的资源上——而这带来一套具体的工程问题。

我在 Reflection 遇到的现实是：**共享 GPU 池，被其他团队抢占是常态**。我自建了一套 pause/resume 框架：

- **动态申领 / 让出资源**：任务能在被抢占时把状态落盘并优雅退出，资源空出来时自动恢复，不需要人工重跑。
- **TCP 式自适应并发调节**：成功就加并发（加性增），在失败窗口内就退（乘性减）。这个类比在面试里非常好用——它把一个听起来平淡的"重试逻辑"变成一个有原理的拥塞控制设计。
- **幂等与断点续跑**：每个生成单元有确定性 ID，重复执行结果一致，这样任意时刻被杀都能续（对应 [07 §14.2](07_pretraining_data.md)）。

**诚实边界**：这是**离线批量**推理的基础设施，不是在线 serving。我没有承担过大规模在线服务的 oncall——涉及 p99 延迟预算、限流降级、多可用区容灾这类问题时，我会说清楚这是我的边界，我知道要考虑什么，但没有生产责任的经验。

## 12. 常见失败模式（这个系统最容易在哪坏掉）

| # | 失败模式 | 症状 | 根因 | 防御 |
|---|---|---|---|---|
| 1 | **在天花板上评测** | 所有方法都 0.98+，看不出差异 | 合成的评测数据太简单，或标签泄漏进了输入 | 造数据时**刻意设计区分度**（下面详述） |
| 2 | **模式坍塌** | 生成 5 万条，去重后剩 8 千 | seed 太少 / 只靠温度求多样性 | §6.2，扩 seed 和条件维度 |
| 3 | **judge 静默漂移** | 通过率没变，下游却退化 | judge 模型版本或 prompt 变了 | judge 锚点集当回归测试（§4.3） |
| 4 | **verifier 放水** | L1 通过率突然从 55% 涨到 90% | verifier 代码 bug（比如异常被吞了当通过） | 通过率突变告警 + verifier 自己的单元测试 |
| 5 | **eval 污染** | 离线 benchmark 猛涨，线上没变化 | generator 记得 benchmark 题目 | 语义近重复检测，不能只做 exact match（[07 §八](07_pretraining_data.md)） |
| 6 | **静默丢掉一整类** | 某能力莫名退化 | 难度筛选或 verifier bug 让某类题被系统性丢弃 | 按类别统计丢弃率（§5.4） |
| 7 | **generator artifact 被学到** | 模型在合成风格上很强，真实输入上不行 | 合成数据有可识别指纹 | C2ST 判别器 + 看 top feature（§8.1） |
| 8 | **难度标签过期** | 训到中期梯度信号骤降 | 用离线固定的难度标签 | 在线探测 + 阈值随 policy 漂移（§5.1） |
| 9 | **代际自噬** | 逐代变平庸、长尾消失 | replace 而不是 accumulate | §7.3 四条防线 |
| 10 | **成本失控** | 账单是预算的 3 倍 | 只算了生成没算筛选；通过率远低于预期 | 先跑 1000 条测通过率，再外推预算 |

**关于 #1，我在自建的 Decagon 备战项目里实测踩到过**（[data/README.md](../projects/decagon_finetune/data/README.md)、[data/generate.py](../projects/decagon_finetune/data/generate.py)）：我造知识库文章时，如果只让 gold 文章包含全部主题术语，BM25 会直接把它送到 top-1、recall 顶到 1.0，后续所有方法就都测不出差异了。**修法是让同主题的多篇近邻文章都含全部术语，只有语义 focus 不同——强制区分度来自语义而非术语泄漏。**

这个坑对**造 eval 数据**是通用教训：**如果你造的评测集上所有基线都拿满分，问题不在方法，在数据。造数据的时候就要把"什么让这道题难"设计进去。** 那个项目里踩到的另外几个坑（训练/推理 prompt 不一致、decoder-only 批量生成必须左 padding、模型复读输入要把兜底率当指标报出来）在 [02_playbook.md](../projects/decagon_finetune/02_playbook.md) 里。

## 13. 10 分钟口述稿

> 我先确认三件事：**合成数据要解决的是哪个问题**——总量不足、长尾覆盖、隐私替代、标注成本还是难度控制；**有没有 verifier**；以及**这批数据用在训练的哪一段**。第一个问题最关键，因为这五个目的对"和真实分布的差距"的要求是相反的：补长尾时我故意要分布偏移，做隐私替代时同样的偏移就是缺陷。
>
> 指标上我只认一件事：**在固定算力、固定其他变量的 ablation 下，加了这批数据的模型在纯真实 held-out 上更好**。generator 的自评、judge 的平均分、"看起来很像真的"都不是证据——它们只说明生成端和评判端有共同偏好。我会在开工前写一份验收合同：主指标、guardrail、污染阈值、多样性下限、provenance 字段、成本上限，还有失败判据。
>
> 生成范式我会混着用。种子来自真实语料——**多样性来自 seed，不来自 prompt**，在 prompt 里写"请多样一点"基本无效。然后跑多阶段流水线：question rewriting、把不可验证的题转成可验证形式、answer rewriting、质量特征打分。我在 Reflection 做 math/STEM 数据就是这条路径，其中**"不可验证转可验证"这一步价值最高**，因为它把下游从"只能靠 judge"变成"可以靠程序"，直接决定了筛选的成本结构。
>
> 筛选是三级漏斗，不是加一个 judge：规则先挡垃圾，verifier 挡硬错误，模型 judge 判语义质量，人工只做分层抽检来校准前三级。judge 我会拆成一组二元判定——是否自包含、是否含矛盾信息、解题假设是否给足——而不是打 1 到 10 分，因为**同一条标准 judge 在不同题目上判得不一致**，这个我实际遇到过。我会给 judge 建一套固定的人工锚点集当回归测试。
>
> 难度这块是我做得最深的。**难度不是题目的属性，是模型的函数**，所以必须在线筛。我们的做法是：正式 rollout 之前先用 16 条小批量探测可解率，全对或全错的直接丢——没有梯度信号，纯烧算力——保留的再跑 128 条。筛选大约占 12% 的算力。这个思想和 DAPO 的 dynamic sampling 是一致的。副作用要主动防：如果某类题的 verifier 有 bug，它们会全部落在"全错"被静默丢掉，所以要按类别统计丢弃率。
>
> 多样性和质量的张力上，温度不是多样性旋钮——它主要在"生成成本"和"筛选成本"之间做交换。真正的杠杆是 seed 多样性和条件维度的笛卡尔积。去重上，合成数据的重复是模式重复不是字符串重复，所以除了 MinHash 还要做 embedding 近邻去重和"骨架去重"，把数字和实体归一化后再比。覆盖度我会做成 taxonomy 网格看板而不是标量分数，因为标量分数不能告诉团队下一批该生成什么。
>
> 模型坍塌我会主动讲。反复自产自销会让分布的尾部先消失，而这时整体指标可能还在涨——这是最危险的阶段。关键的工程结论是 **replace 会坍塌、accumulate 不会**：每代必须保留真实数据，合成只做增量。加上代际标签和比例上限，用一个冻结的参考模型监控分布，再留一个永不参与生成的真实锚定集。这里我要诚实：跨多代自训练的长期实验我没跑过，我遇到过的是单代内的模式坍塌。
>
> 分布偏移我用判别器二样本检验来量——训个分类器区分真实和合成，AUC 接近 0.5 说明不可区分；更有用的是看分类器最看重哪些特征，那就是 artifact 清单，可以直接回去修 prompt。隐私上，**合成不等于匿名**：要做 canary 记忆测试，要防准标识符组合重识别；需要形式保证时用 DP 训练 generator，靠差分隐私的后处理免疫性，采样多少条都不额外消耗隐私预算。
>
> 成本我看的是**每条通过闸门的样本成本**，不是每千 token 单价——一个便宜但通过率 10% 的 pipeline 比贵一倍通过率 60% 的更贵。降本靠分层生成（便宜模型量产、贵模型只做精修和边界仲裁）、批处理接口（约五折）、prompt caching（rubric 前缀固定，缓存读约 0.1 倍）。基础设施上这类任务吞吐敏感、延迟不敏感、可中断，适合跑在抢占式资源上——我自建过 pause/resume 框架和 TCP 式的自适应并发调节。
>
> 最后我会说什么时候不该做：真实数据便宜时、分布极难建模时、没有 verifier 也没有人评预算时、以及要建 eval 集时。**合成数据是信息的重新分配，不是信息的创造**——所以判断一个 pipeline 值不值得做，只要问一句：新信息从哪里进来？

## 14. 面试前一页速记

**五种目的**：总量 / 长尾 / 隐私 / 标注成本 / 难度控制。**对"是否匹配真实分布"的要求相反**——补长尾故意偏，隐私替代必须像。

**唯一有效指标**：matched-compute ablation 在**纯真实** held-out 上的下游提升。generator 自评 / judge 均分 / "像真的" 全都不是证据。

**六种范式**：模板 · zero-shot · self-instruct（ROUGE-L>0.7 去重）· evol-instruct（in-depth + in-breadth + 淘汰失败进化）· 从真实数据反推（backtranslation / rephrase，**首选**）· 蒸馏 + rejection sampling。

**多样性来自 seed，不来自 prompt。**（Cosmopedia 教训）

**三级漏斗**：L0 规则（~0 成本）→ L1 verifier（硬错误）→ L2 模型 judge（语义）→ L3 人工分层抽检（**校准，不是过滤**）。抽检要抽通过的**和**被拒的。

**质量特征拆成二元判定**：自包含 / 无矛盾 / 假设充分 / 答案唯一可判定 / 与 seed 一致。**别打 1–10 分。**

**judge 是需要回归测试的模型组件**：固定人工锚点集 + κ 一致性 + 版本号。

**难度是（题, 模型）的函数**：16 条探测 → 丢全对全错 → 128 条正式；~12% 算力；= DAPO dynamic sampling。RL 要 0<p<1，SFT 要 p→1，eval 要冻结。

**去重三层 + 骨架归一化**：exact → n-gram → embedding 聚类；数字/实体替占位符后再比。**必须对 seed 和所有 eval 集去重。**

**坍塌**：早期尾部先消失（指标可能还在涨）→ 晚期方差塌缩。**replace 会坍塌，accumulate 不会**（保留真实数据）。四防线：真实锚定 / 代际比例上限 / 冻结参考模型监控分布 / 外部真实锚定集。有 verifier 的可验证域风险低。

**分布偏移**：C2ST 判别器 AUC（并看 top feature）· TSTR vs TRTR · precision/recall 分解 · MAUVE。**"越像越好"是错的，取决于目的。**

**隐私**：合成 ≠ 匿名。canary exposure 测记忆；准标识符组合重识别 NER 抓不到；DP-SGD + **后处理免疫性**（采样不额外耗预算）。

**不该做的时候**：真实数据便宜 / 分布极难建模 / 无 verifier 无人评 / 造 eval 集 / teacher 不具备该能力 / 已自产自销两三代。

**成本**：分母是**通过闸门的条数**。分层生成 + 批处理（~50% off）+ prompt caching（读 ~0.1×，写 1.25×/2×，rubric 前缀固定天然契合）。

**必背句 1**：合成数据是信息的重新分配，不是信息的创造——问"新信息从哪进来"。
**必背句 2**：judge 不是 ground truth，是需要被校准和回归测试的模型组件。
**必背句 3**：我不看每千 token 单价，我看每条进库样本的成本。

## 15. 常见追问 + 应答要点

1. **「怎么证明合成数据真的有用？」**
   固定架构/tokenizer/优化器/总 token/eval 版本/多个随机种子，只变"是否加这批数据"，在**纯真实** held-out 上比较，并报置信区间。加做 scaling 检查：在两个模型规模上都有增益才有外推价值——小模型喜欢的数据不一定让大模型受益（[07 §13.4](07_pretraining_data.md)）。不显著就写不显著。

2. **「用 GPT/Claude 生成数据训自己的模型，合规吗？」**
   先看服务条款，很多商业 API 明确禁止用输出训竞品模型。合规路径是用宽松许可的开源权重模型——Nemotron-4 340B 就是明确为这个用途发布的。这是法务约束，我会拉法务确认而不是自己判断。

3. **「多样性和质量怎么权衡？给个具体做法。」**
   不用一个标量去 trade off。做法是：质量设**硬门**（闸门必须过），多样性设**下限约束**（taxonomy 网格覆盖率 ≥ A%、每格 ≥ N 条），然后在满足两者的前提下最大化产量。温度不是这个旋钮——它把成本从生成端推到筛选端而已。

4. **「judge 和 generator 用同一个模型可以吗？」**
   能用但要知道代价：自我偏好会让通过率虚高。缓解——judge 用不同家族的模型；拆成客观二元判定降低主观空间；用人工锚点集测 judge 与人的一致率。**如果只能用同一个模型，就必须把人工抽检比例提上去。**

5. **「怎么知道模型坍塌开始了？」**
   不要看整体指标，看**尾部**：罕见 token 频率、embedding 聚类熵、低频类别的召回、用**冻结**参考模型算的 perplexity 分布的方差。这些会先动，整体指标可能还在涨。

6. **「加多少比例的合成数据合适？」**
   没有通用答案，必须 ablation 扫（5/10/20/40%）。可以引用两侧的文献张力：accumulate 策略下误差有与代数无关的上界；但也有工作指出即便很小比例的合成数据也可能造成可测量的退化。**所以我给的是方法不是数字。**

7. **「合成数据能不能用来做 eval？」**
   一般不行。合成 eval 系统性偏向和 generator 同族的模型，且极易被训练污染。唯一例外是**诊断性 challenge set**——故意构造已知缺陷的样本来测特定失败模式（我在 Anthropic take-home 里做的 137 对扰动测试套件就是这类）。但这类集合是用来**定位问题**的，不能当主指标。

8. **「verifier 本身错了怎么办？」**
   verifier 要有自己的测试集和单元测试。监控它的通过率突变。对被 verifier 判错的样本做分层人工抽检。另外要防"verifier 可被 hack"——比如答案匹配用了过松的正则，模型学会输出一堆数字碰运气命中（对应 [03](03_model_training_reward.md) 的 reward hacking）。

9. **「怎么防止合成数据污染 benchmark？」**
   exact string match 远远不够——generator 可能"重新发明"benchmark 题目。要做 n-gram 重叠 + embedding 近重复检测，且对所有 eval 集都做。并且**不承诺"零污染"**，而是报告检测方法和检出率（[07 §8.3](07_pretraining_data.md)）。

10. **「人工抽检抽多少、怎么抽？」**
    量级上几百到几千条即可（目的是估计准确率，不是过滤）。**关键是分层**：按 judge 判定（通过/拒绝/边界）、按 taxonomy 类别、按 generator 版本分层，这样才能同时估 precision 和 recall，并定位系统性盲区。只抽通过的样本永远发现不了误杀率。

11. **「多语言/低资源语言的合成数据？」**
    最大的问题是 generator 在低资源语言上本身就弱——生成出来的东西可能语法都不对，而你的 judge 也是同一个弱模型，测不出来。做法：以翻译 / 跨语言反推为主（事实来自高资源语言的真实语料），并且**低资源语言的人工抽检比例要显著高于高资源语言**。评估必须用母语者，不能只看翻译过来的 benchmark。

12. **「如果这套系统交给别人接手，最容易出问题的是什么？」**
    provenance 和 judge 版本管理。生成一批数据很容易，难的是半年后有人问"这批数据是哪个模型、哪个 prompt、哪个闸门版本产出的，为什么当时通过率是 32%"。所以每条样本必须带 generator / checkpoint / prompt 版本 / seed 来源 / 闸门通过记录，judge 必须有版本号和固定的回归锚点集。**这条如果做不到，整套系统是不可维护的。**
