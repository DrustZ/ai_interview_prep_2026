## 1. 一句话主张（建议背下来）⭐⭐⭐

> RL 数据流水线的产出物不是「问题 + 标准答案」的语料库，而是**一组带 verifier 的 prompt，且每个 prompt 对当前策略而言处在有梯度信号的难度带里**。所以这条 pipeline 有三个和 SFT 数据完全不同的核心动作：**把不可验证的题改造成可验证的**、**用小批量 rollout 探测难度并丢掉全对/全错的样本**、**用 trace 检测 verifier 被 hack**。这三件事都要花 GPU——它不是一条 CPU 上的数据清洗流水线，它本身就是一次大规模批量推理任务，成本和一次小规模训练同量级。而因为难度是 (题目, 策略, 采样参数) 的联合属性，随着策略变强它会整体漂移，所以筛选阈值必须自适应、被丢掉的「太难」样本要留在 reserve 池里定期回捞。

**90 秒版本**（面试开场用）：

> 我会先问清楚训的是哪个 checkpoint、用什么 RL 算法、组大小多少——因为「这道题合不合适」不是题目的属性，是题目相对这个策略的属性。指标上我不会报「我造了多少条数据」，我报**有效梯度产出率**：一个 batch 里非退化组的比例，以及每 GPU-hour 换来的下游 eval 提升。Pipeline 分四段：**供给**（开源集 + 原始语料转换 + 合成 + 真实用户分布）、**可验证化**（答案抽取 / 单元测试 / 形式化检查 / claim 级 rubric）、**难度筛选**（16 条探测 → 丢全对全错 → 128 条正式，约 12% 算力花在筛选上）、**闭环**（读 trace → 发现失败模式 → 回改前三段）。最大的风险有两个：verifier 的假阳性会被策略主动搜索，所以我对「判对」这一侧要求高 precision；以及难度阈值会随训练漂移，静态筛出来的数据集训到中期就全变成简单题了。

## 2. RL 数据 ≠ SFT 数据 ⭐⭐⭐

这是整题的地基。很多候选人会把「造 RL 数据」讲成「造高质量 QA 对」，那是 SFT 的思路。

### 2.1 对照表

| 维度 | SFT 数据 | RL（RLVR）数据 |
|---|---|---|
| **一条样本是什么** | `(prompt, 参考回答)` | `(prompt, verifier, 元信息)`；**回答由策略自己产生** |
| **「质量高」的定义** | 回答写得对、写得好、风格一致 | **这个 prompt 能产生非零 advantage** |
| **参考答案的作用** | 是训练目标本身 | 只是 verifier 的输入；**如果泄漏进 prompt 就是灾难** |
| **模型太强会怎样** | 无所谓，仍然学得到风格 | **样本直接作废**（全对，组内方差 0） |
| **模型太弱会怎样** | 无所谓 | **样本直接作废**（全错，组内方差 0） |
| **数据量的边际收益** | 大致随 log(N) 上升 | **强烈非线性**：一条 p≈0.5 的题 > 十条 p≈0.98 的题 |
| **重复样本的危害** | 轻微过拟合 | 严重：同一题被反复 rollout，等价于给这个题族加了权重 |
| **数据集的寿命** | 长，可跨模型复用 | **短，绑定 checkpoint**；模型更新后难度标注全部失效 |
| **生产成本主体** | 标注 / 教师模型生成 | **rollout 生成（decode）**，是数据 pipeline 的 80%+ 成本 |
| **典型失败形态** | 学到过时/错误示范 | 学到 hack verifier 的捷径 |

### 2.2 一句可以直接说的话

> SFT 里「好答案」是资产；RL 里「好答案」是**风险**——它只应该存在于 verifier 一侧，一旦泄漏到 prompt 侧（比如爬论坛帖时把楼下的解答一起爬进来了），这道题的 pass rate 会跳到 1.0，然后被我的难度筛选当成「太简单」丢掉。**污染在这里不是让指标虚高，是让我最好的题被静默删掉。**（详见 §8.3，这是本题最反直觉的一个失败模式）

### 2.3 数据集的最小 schema

```jsonc
{
  "prompt_id":        "sha256(canonical_problem_text)",  // 去重主键
  "prompt":           "...",                              // 不含答案、不含解法
  "domain":           "math/olympiad_geometry",
  "source":           "aops_thread_2019 | synth_v3 | user_log",
  "license":          "...",
  "verifier": {
      "type":         "exact_numeric | sympy_equiv | unit_test | rubric_claims | judge",
      "gold":         "...",                              // 或测试用例集合
      "tolerance":    1e-6,
      "version":      "v7"                                // verifier 也要版本化
  },
  "difficulty": {
      "probe_policy": "ckpt_step_4200",                   // ⭐ 难度绑定 checkpoint
      "sampling":     {"T":1.0,"top_p":0.95,"max_tokens":8192},
      "n_probe":      16,
      "p_hat":        0.31,
      "measured_at":  "2026-07-02"
  },
  "flags":            ["self_contained_ok", "no_answer_leak", "single_valued"],
  "contamination":    {"checked_against": ["MATH500","AIME24","GPQA"], "max_sim": 0.42}
}
```

**面试里值得点出的三个字段**：`difficulty.probe_policy`（难度绑 checkpoint）、`verifier.version`（verifier 变了难度标注就失效）、`sampling`（探测和训练的采样参数必须一致，否则 p̂ 系统性偏差，见 §14 失败模式 5）。

## 3. 先问清楚：八个澄清问题 ⭐⭐⭐

每个问题后面那一列是关键——面试官要看的是你知道**这个答案会改变什么**。

| # | 问题 | 答案会改变什么设计决策 |
|---|---|---|
| 1 | **训哪个模型、从哪个 checkpoint 起？基座是已经 SFT 过的还是裸的？** | 决定整个难度分布。同一批题对 8B 全错、对 200B 全对。**如果基座连格式都不稳，RL 之前先补 SFT，这条 pipeline 的第一版就白做**（RL 放大已有能力，不凭空创造） |
| 2 | **RL 算法是什么？GRPO 类（组内归一化）还是带 critic 的 PPO？组大小 G 多少？** | GRPO 类下全对/全错**严格贡献 0 梯度**，难度筛选是刚需；带 value critic 的 PPO 仍能从全对组里得到一点信号（value 基线不等于组均值），筛选可以宽松些。G 决定退化概率（§7.1 的表） |
| 3 | **目标能力是什么？单域（math）还是多域混合（math + code + agentic + 通用推理）？** | 决定要不要做跨域难度归一化、配比方法（§11）、以及 verifier 栈的复杂度。**多域是完全不同的一道题**——单域的 pipeline 可以两周做出来，多域主要成本在跨域可比性 |
| 4 | **终态可以程序化检查吗？可验证的比例大概多少？** | 这是可行性边界。如果 <30% 可验证，先做的不是 pipeline 是**可验证化**（§6）；如果基本不可验证，那这题应该退回 preference/rubric 路线，见 [03 §5](03_model_training_reward.md) |
| 5 | **compute 预算怎么切：数据生成 vs 训练？两者是同一批 GPU 吗？** | 关键约束。**筛选就是 rollout，和训练抢同一批卡**。如果是同一个池子，筛选的 12% 是从训练预算里扣的，要能论证这笔账（§7.2 的成本账） |
| 6 | **有没有真实使用场景的 prompt 分布？** | 决定合成的目标分布。没有的话，合成会不自觉地收敛到「教科书题」，训出来的模型在真实分布上不涨 |
| 7 | **eval 集是哪些？锁定了吗？还会加吗？** | 决定去污范围。**eval 没锁定就要按最坏情况去污**（把整个来源域拉黑而不是只删命中项）。另外要问 eval 是不是也用来做 early stopping——如果是，它已经不是 held-out 了 |
| 8 | **迭代节奏：数据是一次性交付，还是每周/每天出一版跟着训练走？** | 决定架构。一次性 = 批处理脚本；跟着训练走 = 需要增量化、缓存、幂等、和训练器的 checkpoint 同步（§13）。**RL 数据 pipeline 通常是后者，因为难度会漂移** |

> **可选第 9 问**（有安全/合规上下文时问）：有没有必须 hard-gate 的行为？如果有，它不能进 reward 的加权项，必须是独立的一票否决（[03 §6](03_model_training_reward.md)）。

## 4. 指标先于方案：这条 pipeline 怎么算成功 ⭐⭐⭐

### 4.1 先说不能用的指标

| 常见但错的指标 | 为什么错 |
|---|---|
| **产出了多少条数据** | 最容易刷，且和梯度信号完全正交。一百万条全对的题价值为 0 |
| **LLM 打的平均质量分（1–5）** | 「题目写得好」和「有梯度信号」是两个维度。一道措辞完美的送分题质量分 5.0、价值 0 |
| **训练时的 pass rate 上升** | 三种解释：真变强 / 难度筛太松 / verifier 被 hack。**单看它无法区分**，必须配合下游 eval 和长度曲线 |
| **judge 平均分** | judge 会漂移、会被风格骗（§9.3）。作为主指标等于把方向盘交给一个没校准的模型 |
| **verifier 通过率** | 同上，它是被优化的对象，不能同时当尺子（Goodhart） |

### 4.2 该用的分层指标

| 层 | 指标 | 说明 |
|---|---|---|
| **数据产出（快，小时级）** | **有效梯度产出率** = 一个 batch 里非退化组的比例 = `1 − P(全对) − P(全错)` | 这是本篇的核心指标。它直接量化「多少 rollout 算力换来了非零 advantage」 |
| | **有效 token 效率** = 产生非零 advantage 的 rollout token / 总生成 token | 把上一条换算成钱 |
| | **保留率 yield** = 通过全部 gate 的 prompt / 候选 prompt | 决定单位经济学。**yield 太高（>0.9）说明 gate 太松，太低（<0.2）说明供给侧选错了源** |
| | **每条可用 prompt 的成本** | `(C_合成 + C_探测 + C_去污 + C_人工抽检) / yield` |
| **训练动态（天级）** | 组内 reward 方差的分布、策略熵、平均生成长度、truncation 率 | 熵坍缩和长度爆炸是最早的预警信号（§14） |
| **模型质量（周级，最终裁判）** | **固定 compute 下的下游 eval 提升 per GPU-hour** | 唯一能证明「这批数据有用」的方法：加这批 vs 不加的等算力 A/B。对应 [07 §13](07_pretraining_data.md) 的 data ablation ladder |
| **Guardrail** | 与 eval 集的污染率、prompt 重复率、**verifier 假阳性抽检率**、长度中位数、成本/步 | 假阳性抽检率是唯一能提前抓住 reward hacking 的离线指标 |

### 4.3 一句高分句

> 我不会用「产出了多少条数据」汇报。我报的是**有效梯度产出率**——一个 batch 里既不是全对也不是全错的组占多少。这个数字直接可以换算成钱：如果它是 60%，意味着我 40% 的 rollout 预算生成的 token 对应的 advantage 恒等于 0，那些 GPU 小时是纯烧掉的。而它也是唯一一个能同时诊断数据侧（题太简单）和优化侧（熵坍缩）的指标。

## 5. Prompt 从哪来：四条供给线 ⭐⭐

### 5.1 供给线对照

| 来源 | 量级 | 可验证性 | 难度分布 | 主要坑 | 我的经历 |
|---|---|---|---|---|---|
| **开源数据集**（MATH、GSM8K、NuminaMath、CodeContests…） | 10⁵–10⁶ | 高（已带答案） | **偏简单**，前沿模型基本全对 | ①**已被榨干**——所有人都在用，边际收益接近 0；②**污染重灾区**，很多题就是 eval 的近亲 | 作为起点和 baseline，但不是主要产能 |
| **原始语料转换**（教材、Stack Exchange、论坛、竞赛题库、讲义 PDF） | 10⁶–10⁷ | **低，要造**（§6） | 覆盖宽，含真正的难题 | ①格式脏（LaTeX/OCR/图片题）；②答案散落在讨论里；③大量题**不自包含**（引用「上一题」「图 3」） | ⭐**这是我在 Reflection 的主线**：多阶段 LLM 流水线做 question rewriting / answer rewriting / QA 转换 |
| **合成**（从 seed 变异、逆向构造、组合难化） | 无上限 | 高（构造时就带答案） | **可控**，这是它最大的价值 | ①**多样性坍缩**——种子少的话生成的题互为改写；②教师模型的能力上界就是难度上界；③逆向构造出的题常常「不像人会问的题」 | ⭐做过，配合 §8 的语义去重才可用 |
| **真实用户/产品分布** | 10³–10⁵ | 通常低 | 反映真实需求 | 量少、隐私、且**没有 gold answer**——最需要 §6 的可验证化 | 边界：mid-training 侧接触有限，见 §19 |

**一句话取舍**：开源集用来对齐 baseline 和快速验证 pipeline 通不通；**真正的产能在原始语料转换**（量大、难度高、且别人没榨过）；合成用来**填难度空洞**（发现某个难度带/某个 topic 样本不够时定向补），不作为主要来源；真实分布量少但用来定义「合成往哪个方向靠」。

### 5.2 原始语料 → 可训练 prompt 的多阶段流水线（我做过的）

这是可以在白板上直接画的部分：

```text
原始文档（教材章节 / SE 帖子 / 竞赛 PDF / 讲义）
  │
  ├─ S0 结构化解析：LaTeX 修复、图片题剔除、题目-解答边界切分
  │      （失败率最高的一级；OCR 出来的 \frac 错位会静默污染整批）
  ├─ S1 抽题：从长文档里定位「这是一道题」的片段
  ├─ S2 question rewriting：改写成自包含、无歧义、假设完整的题面
  │      ⭐ 同时剥离答案 —— 这一步做不干净就是 §2.2 的答案泄漏
  ├─ S3 answer rewriting：从散落的讨论里归纳出唯一的、格式规范的最终答案
  ├─ S4 QA 转换：不可验证形式 → 可验证形式（§6）
  ├─ S5 质量特征打标（下表）+ 规则/分类器过滤
  ├─ S6 去重（surface + semantic + 解法骨架，§8）
  ├─ S7 去污（vs 全部 eval 集，§8.3）
  └─ S8 难度探测（§7）→ 入库
```

每一级都要报**通过率**和**成本**，形成 funnel dashboard（和 [07 §15.2](07_pretraining_data.md) 一样的结构，但每级的判据完全不同）。

### 5.3 质量特征清单（S5 打的标）

这几条是我实际用过的判据，比「质量高不高」可操作得多：

| 特征 | 检查什么 | 不合格的典型 | 处理 |
|---|---|---|---|
| **自包含** | 不引用外部上下文 | 「承上题」「如图所示」「用课本定理 4.2」 | 能补全就补全（S2 改写），不能就丢 |
| **无矛盾信息** | 题设内部不冲突 | 「等腰三角形，三边分别为 3、4、5」 | 丢。这类题会让模型学会「胡诌一个答案」 |
| **假设充分** | 解题所需条件都给了 | 缺定义域、缺单位、缺初始条件 | 补条件（会改变难度，要重新探测） |
| **答案唯一** | 不存在多个合法答案 | 「举一个例子」「说出一种方法」 | 转成可验证形式（§6）或丢 |
| **无答案泄漏** | 题面里没有最终答案 | 「证明 S = n(n+1)/2」（答案就在题面） | 改写成「求 S」，或丢 |
| **格式可解析** | 最终答案能被抽出 | 答案是一段散文 | 强制 `\boxed{}` 约定 |

> **面试可讲的细节**：「无矛盾信息」这条是我加的，因为它对 RL 的危害和对 SFT 完全不同。矛盾题在 SFT 里只是一条噪声样本；在 RL 里它的 pass rate 会稳定在某个非零的低值（模型偶尔蒙对 verifier 期望的答案），于是它**恰好落在我的难度保留带里**，被当成「有价值的难题」大量 rollout。**难度筛选会主动把矛盾题捞出来。** 所以质量 gate 必须在难度探测之前。

## 6. 可验证性：把不可验证的题变成可验证的 ⭐⭐⭐

### 6.1 可验证性谱系

| 级别 | 形式 | 例子 | 假阳性风险 | 成本 |
|---|---|---|---|---|
| **L0 精确匹配** | 归一化后字符串相等 | 整数答案 | 极低 | ~0 |
| **L1 符号等价** | sympy / 数值容差 / 单位归一 | `1/2` vs `0.5` vs `\frac12` | 低（但要防 sympy 超时/误判） | 低 |
| **L2 执行验证** | 单元测试、编译、运行 | 代码题 | 中（测试不完备 → 可过拟合） | 中（sandbox） |
| **L3 形式化检查** | Lean/Coq 通过、schema 校验、约束满足 | 定理证明、结构化输出 | 极低 | 高（形式化成本） |
| **L4 claim 级 rubric** | 拆成 N 个独立 yes/no 检查 | 长回答、grounding | 中 | 中（每 claim 一次判定） |
| **L5 整体 judge** | LRM 打分/比较 | 开放写作 | **高** | 中–高 |

**核心判断：能往 L0–L3 走就绝不停在 L5。** 不是因为 L5 不准，而是因为 §9.4 的不对称性——L5 的假阳性会被策略主动搜索。

### 6.2 三条转换路径（把 L4/L5 拉到 L0–L2）

**路径 A · 答案抽取（最常用）**

- 从散文式解答里归纳出**唯一的最终量**，并规定格式（`\boxed{}`、单位、精度、多答案的排序规则）。
- 关键实现细节：**归一化必须双向**。`0.5` / `1/2` / `\frac{1}{2}` / `50\%` 要能互认，否则是假阴性；但 `[1,2]` 和 `[2,1]` 要不要互认取决于题意，写死一个规则会同时制造两类错误。做法是让 S3 阶段**同时输出答案和它的类型**（scalar / set / tuple / interval / expression），按类型选比较器。

**路径 B · 单元测试化**

- 代码题：从参考解 + 输入生成器生成测试用例；**测试的覆盖度决定假阳性率**。
- 非代码题也能测试化：一道「设计一个满足 X 的算法」可以转成「实现它并通过这 20 个用例」。
- 坑：用参考解生成期望输出，参考解本身错了就整批污染。要求参考解至少通过一次交叉验证（两个独立实现一致）。

**路径 C · 形式化 / 结构化检查**

- 证明题 → 要么形式化（贵），要么**降级成可数值化的推论**：「证明 ∑=n(n+1)/2」→「求 n=1000 时的 ∑」。
- ⚠️ **这个降级会改变任务**：证明变成了计算，可能从 olympiad 难度掉到小学难度。**转换后必须重新探测难度**，不能沿用原题的难度标签。这是 QA 转换最容易被忽略的代价。

**路径 D · claim 级 rubric（当 A/B/C 都不行时）**

把「这个回答好不好」拆成 N 个可独立判定的原子命题，每个命题让 judge 只回答 yes/no，最终 reward = 满足比例（或全满足才给分）。

> ⭐ **这里我有直接证据可以讲**（Anthropic take-home，医疗域，可公开讲）：我做过一个对照——用 ROUGE 这类整体相似度指标去预测「医生标注为不安全的回复」，AUROC 只有 **0.569**，基本是掷硬币；把同一个任务拆成 **claim 级 grounding** 逐条判定，AUROC 到 **0.844**，两者置信区间不重叠。**结论可以直接迁移到 RL reward 设计上：整体打分的 judge 之所以不一致，很大程度上不是模型笨，是我们让它一次做了太多判断。缩小 judge 的作用域，一致性会显著上升。**

### 6.3 什么时候**不该**转

| 情形 | 为什么不转 |
|---|---|
| 转换会把题变平凡 | 见路径 C 的警告。转完要重新探测，发现 p→1 就该丢，而不是留着凑数 |
| 题目的价值就在开放性 | 「设计一个实验」「权衡两个方案」——强行数值化会训出只会报数字的模型 |
| 转换后的答案不唯一但你假装唯一 | 制造系统性假阴性，模型会学会去猜「verifier 想要哪个形式」而不是解题 |
| 转换本身要调用比被训模型更强的教师 | 那你的数据难度上界 = 教师能力，RL 学不到超出教师的东西（这正是 RL 相对蒸馏的价值所在，别把它抵消掉） |

## 7. 难度筛选与 curriculum ⭐⭐⭐（本篇最重的一章）

### 7.1 为什么全对/全错的样本价值为 0

GRPO 类算法对一个 prompt 采样 G 条回答，得到 reward `r_1..r_G`，优势为

```
A_i = (r_i − mean(r)) / std(r)          # 标准 GRPO
A_i =  r_i − mean(r)                    # Dr.GRPO 等去掉 std 归一化的变体
```

- **全对**（`r_i ≡ 1`）或**全错**（`r_i ≡ 0`）→ `r_i − mean(r) ≡ 0` → **所有 A_i = 0** → 这个 prompt 对策略梯度的贡献严格为零。
- 注意去掉 std 归一化并不能救它：分子就是 0。**这不是数值问题，是结构性的**。
- 而它**照样消耗了 G 条 rollout 的 decode 算力**——这是纯浪费。

**二元 reward 下，组内方差 = p(1−p)，在 p = 0.5 处最大。** 所以「理想 prompt」是当前策略对半开的题。

**退化概率**（真实通过率 p，组大小 G）：`P(退化) = p^G + (1−p)^G`

| p | G=8 | G=16 | G=64 |
|---|---|---|---|
| 0.50 | 0.8% | ~0% | ~0% |
| 0.70 | 5.8% | 0.3% | ~0% |
| 0.80 | 16.8% | 2.8% | ~0% |
| 0.90 | 43.0% | 18.5% | 0.1% |
| 0.95 | 66.3% | 44.0% | 3.8% |
| 0.99 | 92.3% | 85.1% | 52.6% |

> ⭐ **这张表是本节最值得背的东西**。它给出一句极有说服力的话：**如果我的数据池平均 p≈0.9、G=8，那 43% 的 rollout 预算生成的 token，其 advantage 恒等于 0。** 这不是「效率略低」，这是接近一半的算力在空转。而一个只看「pass rate 在涨」的团队完全看不见这件事。

**⭐⭐⭐ 关键补充：组内优势为 0 有两个来源，只有一个是数据问题**

| 来源 | 症状 | 归属 | 数据侧能不能修 |
|---|---|---|---|
| **题目退化**（太简单/太难） | pass rate 分布双峰在 0 和 1 | 数据侧 | ✅ 就是本节在做的事 |
| **熵坍缩** | 策略熵持续下降，G 条 rollout 内容几乎逐字相同，于是 reward 也相同 | 优化侧（KL 系数、clip、温度、lr） | ❌ **筛数据完全没用** |

这个区分是高分点。面试官问「你怎么保证 batch 里有梯度」时，只答难度筛选是不完整的：**同时要监控策略熵和组内回答的多样性**（比如组内 pairwise 编辑距离 / 答案唯一值个数）。我见过的情况是难度分布明明健康，但熵掉下去之后组内答案全一样，有效梯度产出率一样崩。

### 7.2 探测 rollout：两阶段设计与成本-收益 ⭐⭐⭐

**我实际用的方案**：正式 rollout 之前，先用 **16 条**小批量探测通过率；**全对或全错的直接丢弃**（没有梯度信号），保留下来的再跑 **128 条**正式 rollout。**约 12% 的算力用于筛选。**

**为什么 16 是个好数字**——这是可以现场算给面试官看的：

用 n=16 探测、以「全对或全错」为丢弃判据，一个真实通过率为 p 的题被误丢的概率是 `p^16 + (1−p)^16`：

| 真实 p | 被误丢概率 | 判断 |
|---|---|---|
| 0.5 | 3×10⁻⁵ | 几乎不可能误丢 |
| 0.3 / 0.7 | 0.33% | 安全 |
| 0.2 / 0.8 | 2.8% | 安全 |
| 0.1 / 0.9 | 18.5% | 开始丢 |
| 0.05 / 0.95 | 44% | 丢掉近一半 |
| 0.02 / 0.98 | 72% | 大部分丢掉 |
| 0.01 / 0.99 | 85% | 基本丢光 |

> **这正是我们想要的形状**：n=16 的「全对/全错」判据是一个**极度保守的过滤器**——对真正有用的题（p ∈ [0.2, 0.8]）误杀率 <3%，但对退化题（p > 0.95 或 < 0.05）能捞掉近一半到大部分。它不是一个精确的难度估计器（16 个样本估 p 的标准误约 0.12），**但我们不需要精确估计 p，我们只需要区分「退化」和「不退化」**，而这个判据对后者恰好非常敏感。面试里把这句话说出来，比报一个阈值有说服力得多。

**成本账**（记 keep rate = k）：

```
每个候选题的算力  = 16 + k × 128
筛选占比          = 16 / (16 + 128k)
朴素做法（不筛）  = 128
```

| k（保留率） | 筛选占比 | 相对朴素做法的总算力 | 场景 |
|---|---|---|---|
| 0.85 | **12.8%** | 0.98× | 已经过质量 gate 的干净池 → **筛选是质量闸门，不是省钱手段** |
| 0.60 | 17.2% | 0.73× | 混合池 |
| 0.40 | 23.8% | 0.53× | 原始语料首过 → **省一半算力** |
| 0.20 | 38.5% | 0.33× | 极难/极脏的池子 |

> ⭐ **这里有个必须说清楚的 nuance**，说出来会显得你真的算过账：**当保留率很高时，探测几乎不省 decode 算力（0.98×）——它的价值不在省钱，在于保证进入训练 batch 的每一条都有梯度。** 我实际的 12% 对应保留率约 0.85，说明我的上游质量 gate 已经把大部分垃圾滤掉了，探测在这个位置扮演的是**最后一道闸门**。而如果你直接对原始语料探测（k≈0.4），它同时是省一半算力的手段。**同一个机制在 funnel 的不同位置，ROI 论证完全不同。**

**为什么不用一次性 128 条然后按 p 筛？** 因为退化题占比不小，128 条里有 15%–60% 的算力是浪费的；两阶段把这部分成本压到 16。反过来也不该把探测降到 4 或 8：n=8 时 p=0.8 的题误丢率升到 16.8%，开始伤到有用样本。

### 7.3 和 DAPO dynamic sampling 的关系 ⭐⭐⭐

我这套离线两阶段探测，和 **DAPO（ByteDance Seed, 2025）的 dynamic sampling** 在**思想上是同一件事**：都是「丢掉 accuracy 恰为 0 或 1 的 prompt，保持 batch 里全是有效梯度」。DAPO 的做法是**在训练循环内**过采样并持续补充，直到 batch 被非退化 prompt 填满。

| | **离线预筛（我的做法）** | **在线 dynamic sampling（DAPO）** |
|---|---|---|
| 难度估计相对于谁 | **探测时的 checkpoint**，会过期 | **当前策略**，永远准确 |
| 算力花在哪 | 数据 pipeline，可与训练解耦、错峰、抢占式跑 | **训练循环内**，直接拖慢每步 |
| 每步耗时 | 稳定 | **可变**（要等 batch 填满），分布式下同步开销明显 |
| 结果可复用 | ✅ 跨实验复用探测结果 | ❌ 每次训练重跑 |
| 对漂移的鲁棒性 | ❌ 需要定期重探（§7.4） | ✅ 天然自适应 |
| 实现复杂度 | 低（离线批处理） | 中（要改训练循环 + 采样器） |

**我的答案是两者叠加**，理由是它们的成本结构互补：

```
离线粗筛（便宜、可抢占、可复用）—— 干掉「对任何近期 checkpoint 都退化」的题（占大头）
        ↓  保留率 k ≈ 0.85 的数据池
在线细筛（贵但精确）—— 处理漂移带来的残余退化（占小头）
```

**一句可以直接说的话**：如果只做在线过滤，我会在训练循环里反复为同一批注定退化的题付 rollout 费用，而且每次实验都重付一遍；如果只做离线预筛，训到中期数据就整体变简单了。所以离线负责「批量、可复用、可抢占」的部分，在线负责「贴合当前策略」的残差。**顺带一提，DAPO 的另外三个 trick 里，overlong reward shaping 直接对应我在 §10 说的失控推理——把超长截断的样本一刀切给 0 是有害的噪声惩罚，因为那条轨迹可能本来是对的。**

### 7.4 阈值必须自适应：难度会漂移 ⭐⭐⭐

**难度不是题目的属性，是 (题目, 策略, 采样参数) 三元组的属性。** 策略在训练中变强，整个数据池的 p 分布向右漂移：

```
step 0     ████▄▂           训练池 p 分布，众数 ≈ 0.35，健康
step 2000    ▂▄████         众数 ≈ 0.75，有效梯度产出率开始掉
step 5000       ▂▂████████  众数 ≈ 0.95，一半以上的组退化 → 训练实际上停了
```

**自适应机制**（我会这么设计）：

1. **目标带而不是目标点**：维持训练池的 p 分布集中在 **[0.2, 0.8]**，众数在 0.4–0.6。不追求全都是 p=0.5——纯 0.5 的池子没有「稳定拿分」的锚点，容易配合熵坍缩一起崩。
2. **在线估计、免费获取**：训练本身就在跑 rollout，**每个 prompt 的当前 pass rate 是训练循环的副产品，不用额外花钱**。用它维护一个滑动窗口的 p̂。
3. **触发式重探**：当训练池的平均 p̂ 越过上界（比如 0.75），触发对 **reserve 池**的重新探测。
4. **⭐ reserve 池是关键设计**：早期被判为「全错」丢掉的题**不能真删**，要进 `too_hard_reserve`，因为它们正是几千步之后的燃料。同理 `too_easy` 也留档（用于回归检测能力退化）。**我见过的最常见浪费就是把 too_hard 直接 drop 掉，等模型变强了发现没有难题可训，只好重跑一遍全量 pipeline。**
5. **重探成本可控**：重探只需要 n=16，且只探 reserve 池的一个抽样子集（比如 5%）来估计整池的漂移量，再决定是否全量重探。

**Curriculum 的排布**：分桶（p̂ ∈ [0.05,0.2) / [0.2,0.5) / [0.5,0.8) / [0.8,0.95]）后按比例混合，而不是「先易后难」的阶段式。理由：

| 排布方式 | 问题 |
|---|---|
| 阶段式（先全易后全难） | 阶段切换时分布突变，容易触发不稳定；且简单阶段结束后能力会遗忘 |
| **按桶比例混合（推荐）** | 分布平滑，比例本身可随漂移自适应调整 |
| 完全按 p̂ 排序的严格 curriculum | 过度工程，且 p̂ 的估计误差（n=16 时 SE≈0.12）根本支撑不了细粒度排序 |

### 7.5 这套机制什么时候会失效

| 失效条件 | 表现 | 对策 |
|---|---|---|
| **verifier 有假阴性** | p̂ 系统性偏低，真正简单的题被当成中等难度留下 | 对被判「全错」的题抽样人工看，区分「模型不会」和「verifier 判错」 |
| **verifier 有假阳性** | p̂ 虚高，题被当成太简单丢掉；同时 hack 路径被保留 | §9.4、§10 |
| **探测用的采样参数 ≠ 训练** | 尤其是 `max_tokens`：探测给 4k、训练给 16k，长 CoT 题的 p̂ 被系统性低估 | schema 里锁死 sampling 参数并在使用时校验（§2.3） |
| **探测用旧 checkpoint / 教师模型** | 难度标注对当前策略无意义 | 记录 `probe_policy`，超过 N 步就标记为 stale |
| **题目本身高方差**（答案空间大，蒙对概率不稳） | p̂ 的置信区间宽，筛选噪声大 | 这类题提高 n_probe，或直接按 domain 设不同 n |
| **组内多样性坍缩** | p̂ 健康但实际组内 reward 无方差 | 监控熵 + 组内答案唯一值数（§7.1） |

## 8. 去重与污染 ⭐⭐

### 8.1 为什么 RL 比 pre-training 更怕重复

Pre-training 里一条重复文本多看几遍，代价是轻微记忆化。RL 里一道重复的题意味着：

1. 这个题族在训练中的**有效权重被放大 k 倍**（k = 重复数），梯度被它主导；
2. 它的**难度估计是相关的**（同族题一起对、一起错），于是要么整族被留、要么整族被丢，筛选的方差被放大；
3. 更糟：策略会**过拟合这个题族的解法模板**，而 pass rate 曲线看起来是在涨。

### 8.2 三层去重 + 一层「解法去重」

| 层 | 方法 | 抓什么 | RL 特有的注意点 |
|---|---|---|---|
| **Exact** | 归一化后 hash（去空白/LaTeX 规范化/数字保留） | 完全一致 | 归一化不能把数字也抹掉——`n=100` 和 `n=1000` 是不同的题 |
| **Near** | MinHash + LSH（细节见 [07 §6.3](07_pretraining_data.md)，此处不重复） | 换措辞、换变量名 | 阈值要比 pretraining 松（更激进地删），因为重复代价更高 |
| **Semantic** | 题面 embedding 聚类 | 同题不同表述、翻译版本 | 合成数据必须过这一层，否则种子少时会大面积自相似 |
| **⭐ 解法骨架去重** | 用**模型自己的 CoT** 提取解法骨架（用到的定理序列 / 变换步骤），对骨架做聚类 | **数字不同但解法完全相同的题** | 这是 RL 特有的一层：对学习而言，两道解法模板相同的题就是重复样本，即便题面 embedding 距离很远 |

> **解法骨架去重是这一节的高分点**：面试官通常只期待你说 exact/near/semantic 三层（那是 pretraining 的标准答案）。加上第四层并说清「学习意义上的重复不是文本重复」，是一个明显的区分信号。代价是它需要先跑一遍 rollout 才能拿到 CoT，所以自然放在难度探测之后——**探测的 16 条 rollout 可以顺手复用来做解法聚类，边际成本接近 0**。

### 8.3 污染：三种类型 + 一个反直觉的后果

| 类型 | 描述 | 检测 |
|---|---|---|
| **直接污染** | 训练 prompt 和 eval 题近重复 | n-gram / MinHash vs 全部 eval 集 |
| **答案污染** | 题不同但来源同一个题解站，答案键泄漏 | 按 source domain 整体拉黑，而不是逐条删 |
| **模型中介污染** | 合成时用的教师模型记住了 eval 题，生成出它的改写版 | n-gram 抓不到 → 需要 embedding top-k 邻居 + LLM 判「是不是同一道题」 |

**⭐ 反直觉的后果（这一段建议主动讲）**：

> 大家默认污染的危害是「eval 虚高」。但在这条 pipeline 里，污染还有一个更隐蔽的危害：**被污染的题 pass rate 会跳到接近 1.0，于是被我的难度筛选当成「太简单」静默丢弃。** 结果是我的去污和难度筛选在做同一件事的一部分——但难度筛选是**无声**的，我永远不会知道我丢掉的是什么。所以去污必须在难度探测**之前**做，并且要**记录**每一条因污染被删的样本，而不是让它们混在「太简单」那一堆里。

**另一个必须说的**：绝不承诺「零污染」。承诺的是**可审计的污染率上界**和检测方法（同 [07 §8.3](07_pretraining_data.md)）。

### 8.4 答案泄漏的一个便宜检测手段

> 让模型在**禁止 CoT、必须立即给答案**的模式下（`max_tokens=8`，强制格式）跑一遍。如果一道号称竞赛难度的题在这个模式下准确率显著高于基线，那答案大概率可以从题面表面恢复——要么是题面里写了，要么是它被记住了。**这个探针很便宜（8 个 token），可以对全量跑。**

## 9. Reward 的来源与验证 ⭐⭐⭐

通用的 reward 结构、provenance 表和防 hacking 清单在 [03 §6–§7](03_model_training_reward.md)，**这里只讲 RL 数据 pipeline 特有的部分**。

### 9.1 三类来源在 RL 数据侧的分工

| 来源 | 覆盖的题型 | 假阳性来源 | 我的做法 |
|---|---|---|---|
| **规则 / 符号等价** | 数值、表达式、集合 | 归一化过松（`包含 "5"` 就算对）、sympy 误判 | 按答案类型分派比较器；**禁止「任意位置出现即算对」的匹配** |
| **单元测试** | 代码、可执行任务 | 测试不完备、模型 hard-code | 隐藏测试集 + 对抗用例；参考解交叉验证 |
| **LRM-as-judge** | 前两者覆盖不到的 | 风格偏好、位置偏好、跨题标准漂移（§9.3） | **尽量降级成「抽答案 + 规则比较」**，把 judge 的作用域压到最小 |

### 9.2 一个具体的规则设计原则

> **匹配要严格，等价要宽松。** 「严格」指答案必须出现在约定位置（`\boxed{}` 里、最后一行），不接受在推理过程中任意位置扫描；「宽松」指一旦抽出来，`1/2`、`0.5`、`\frac{1}{2}` 要互认。
>
> 把这两件事搞反是最常见的 verifier bug：宽松匹配 + 严格等价 = 模型学会**枚举一串候选答案**（「可能是 3，也可能是 5，或者 7」），只要正确答案在里面就通过。这是我见过的最经典的 verifier hack，而且它在 pass rate 曲线上看起来完全正常。

### 9.3 LRM-as-judge 的一致性问题（我的真实经历）

**我遇到的具体问题**：同一套评判标准，judge 在不同题目上判得不一致——同样是「解法有一步跳跃」，在 A 题上判过、在 B 题上判不过。

**为什么会这样**（可以讲的分析）：judge 被要求同时做三件事——理解题目、复核解法、按 rubric 打分。当题目本身的难度变化时，judge 用于「理解题目」的能力预算变化，剩给「按标准打分」的部分就不稳定。**这不是 prompt 写得不够清楚的问题，是任务负载的问题。**

**怎么量化不一致**（面试官很可能追问）：

| 检验 | 做法 | 健康线 |
|---|---|---|
| **test–retest** | 同一个 (prompt, response) 在 T>0 下判 N 次 | 自一致率；<90% 说明 judge 本身就是噪声源 |
| **顺序/位置交换** | pairwise 判定时交换两个回答的位置 | 翻转率应 <10% |
| **锚定集漂移** | 一组人工标注的固定样本，每次 pipeline 运行都重判 | 跨批次一致率；换 judge 版本时必查 |
| **跨域校准** | 分域统计 judge 通过率 vs 人工抽检通过率 | 差值 >5pp 说明该域系统性宽/严 |

**修法的优先级**（这个排序本身是观点）：

1. **缩小作用域**（最有效）：能抽答案就别让 judge 读全文。judge 只做「这两个表达式等价吗」比「这个解法对吗」一致得多。
2. **拆成 claim 级 yes/no**（§6.2 路径 D，有 0.569 → 0.844 的实测支撑）。
3. 给 few-shot 锚例，且锚例要**跨难度**覆盖。
4. 多 judge 投票——**最后才用**，因为它成本翻倍且掩盖问题而不是解决问题；共享盲区不会被投票消除。

### 9.4 ⭐⭐⭐ 两类 verifier 错误的代价严重不对称

| | **假阳性**（错的判成对） | **假阴性**（对的判成错） |
|---|---|---|
| 对梯度的影响 | **强化了错误行为** | 只是噪声 |
| 会不会被放大 | **会**——策略会主动搜索 FP 区域，这是一个对抗过程，危害随训练时间**增长** | **不会**——策略没有动机去撞它 |
| 对难度估计的影响 | p̂ 虚高 → 好题被当简单题丢 | p̂ 偏低 → 简单题被当好题留（相对无害） |
| 表现 | pass rate 上翘但下游 eval 不动 | 训练慢、天花板低 |
| 设计取向 | **「判对」这一侧必须高 precision** | 可以容忍一定比例 |

**一句可以直接说的话**：

> verifier 的两类错误在 RL 里代价不对称好几个数量级。假阴性只是给梯度加噪声，策略没有动机去利用它；假阳性是被策略**主动搜索**的——RL 的整个机制就是找到能拿高 reward 的路径，而假阳性区域正是免费高 reward 的所在。所以我在设计 verifier 时是 **precision-first on the positive label**：宁可漏判一些正确答案，也不要放过一个错误答案。这也是为什么我不愿意用「宽松匹配」——它换来的召回率提升，代价是打开了一个 hack 通道。

## 10. Reward Hacking 的检测：从 trace 里看 ⭐⭐⭐

**这一节讲的是我实际做过的事：手动读 trace，发现学习行为异常。** 这在面试里非常值钱，因为绝大多数候选人只会说「要防 reward hacking」，说不出「我是怎么看见它的」。

### 10.1 四种我实际观察到的模式

| 模式 | 症状（trace 里长什么样） | 自动检测信号 | 数据侧的修法 |
|---|---|---|---|
| **格式化推理** | 输出有推理的**外形**（"Let me verify…"、"Wait, reconsider…"），但中间步骤和最终答案**没有因果关系**——删掉推理答案不变 | ① **CoT 消融**：截断推理强制立即作答，准确率**不掉** → 推理没做功；② 组内 CoT 的 n-gram 重复率飙升；③ 长度涨但准确率平 | 检查是不是**题太简单**（答案能直接背出来，推理只是仪式）→ 提高难度带；检查 reward 里有没有变相奖励长度 |
| **失控推理** | 反复自我怀疑、循环重述、撞 `max_tokens` 被截断 | truncation 率按题族分组统计；长度分布出现 p99 贴顶的尖峰 | ① 定位诱发它的题族（常见是「讨论所有情况」「是否存在」这类开放题）；② **不要对截断样本一刀切给 0**——那是噪声惩罚，用 DAPO 式的软长度惩罚（缓冲区内线性衰减） |
| **错误推理侥幸答对** | 中间步骤明显错，最终答案却对 | ① 抽样让 judge **只判过程**、不看答案，与结果 reward 求不一致率；② 答案空间小的题（是/否、小整数）**天然高危** | 这是**过程奖励 vs 结果奖励**的经典场景；数据侧的修法是给小答案空间的题**降权或改造**（要求给出中间量），而不是全靠 reward 补救 |
| **答案泄漏 / verifier hack** | 输出里枚举多个候选答案；或直接复述题面里的数字；或代码题里 hard-code 测试用例 | ① §9.2 的严格位置匹配就能挡掉枚举；② §8.4 的 no-CoT 探针抓泄漏；③ 代码题：隐藏测试 vs 公开测试的准确率**落差** | 回到 §5.3 的 `no_answer_leak` gate 和 §6 的 verifier 设计 |

> ⭐ **过程 vs 结果奖励我有实测数据可引**（[decagon_finetune L5](../projects/decagon_finetune/levels/level5_process_reward/)，153 条轨迹的对照）：在一个多步流程任务里，**只看最终结果的 reward 对「合规」与「跳步骤」完全无法区分——两者都是 1.000**；而一旦给工具调用加上效率惩罚，**跳过校验步骤的轨迹反而严格胜出（0.800 vs 0.750）**，因为它少调了一次工具还拿到了同样的结果。这个数字很适合用来说明「结果 reward 的盲区不是理论担忧，是可以构造出来量出来的」。

### 10.2 读 trace 的可操作协议

「手动看 trace」不能是随机翻。我用的是**分层抽样 + 固定节奏**：

| 抽哪些 | 为了找什么 | 每轮条数 |
|---|---|---|
| **reward 最高的 N 条** | reward hacking（最高分往往是钻空子的） | 20 |
| **同一 prompt 组内 reward 方差最大的** | verifier 不稳定 / 题目歧义 | 20 |
| **pass rate 跨 checkpoint 从 ~0 跳到 ~1 的 prompt** | **verifier 假阳性被发现的瞬间**——这是最强的 hack 信号 | 全部（通常很少） |
| **长度 p99 的** | 失控推理 | 20 |
| **新数据源的随机样本** | pipeline bug（解析错误、格式错乱） | 20/源 |
| **下游 eval 上出现回归的题** | 训练数据引入的负面行为 | 全部 |

节奏：**每个训练 run 至少两次**（早期一次抓 pipeline bug，中后期一次抓 hacking），加上每次数据源变更后一次。

**一句高分句**：

> 读 trace 不是「有空看看」，它是这条 pipeline 唯一能发现**我没预料到的失败模式**的手段。所有自动指标都只能检测我已经想到的问题；trace 是唯一的 open-ended 通道。所以我把它做成有固定抽样规则和固定节奏的例行动作，而不是靠直觉抽查。

## 11. 数据配比与 batching ⭐⭐

### 11.1 多域比例怎么定

| 方法 | 做法 | 什么时候用 | 失效方式 |
|---|---|---|---|
| **目标反推** | 按 eval / 产品分布配比 | 目标明确、eval 可信时的默认起点 | **eval 分布 ≠ 最优训练分布**。eval 上占 10% 的能力可能需要 30% 的训练数据才学得动 |
| **yield 驱动** | 按各域「非退化 prompt」的产出量分配 | 早期数据紧张时 | **会坍缩到最容易验证的域**（数学挤掉开放推理），因为可验证性和产出量正相关 |
| **学习进度驱动**（推荐做主机制） | 按各域近期 eval 提升速率分配（多臂老虎机 / prioritized replay 的思路） | 中后期 | **饿死慢域**：安全、长程任务提升慢但重要 → 必须设**比例下限** |
| **固定不动** | 拍一个比例训到底 | 只在做 ablation 需要控制变量时 | 无法响应漂移 |

**我会怎么组合**：`每域比例下限（保底） + 剩余份额用学习进度分配 + 一条冻结配比的 canary run 做对照`。最后那条 canary 很重要——**没有对照组的话，你无法区分「自适应配比有用」和「训练本来就会涨」**。

**跨域难度不可比是个真问题**：math 的 p=0.5 和 code 的 p=0.5 不是同一件事（code 的 verifier 更严、部分得分结构不同）。做法是**按域各自维护难度带和归一化统计量**，而不是全局用一个阈值。

### 11.2 Interleaved batching：为什么不能按域分 batch

| 做法 | 优点 | 问题 |
|---|---|---|
| **域同质 batch**（一步全是 math，下一步全是 code） | 调度简单（同域 verifier 延迟一致，sandbox 可批量复用） | ① 梯度方向逐步切换，产生**振荡**，且优化器的近期记忆偏向最后见到的域；② reward 尺度分域不同 → 每步的 advantage 尺度跳变，和 Adam 的二阶矩估计相互作用（它适应得比域切换慢）；③ 任何 per-batch 归一化（advantage std、token 级 loss 归一）变成**域条件的**，跨步不可比 |
| **Interleaved（样本级混合，推荐）** | 梯度平稳、归一化统计量可比、每步都是「平均任务」 | **verifier 延迟差异巨大**：数学正则是微秒级，代码 sandbox 是秒级 → 慢 verifier 会 stall 整步 |

**解法**：在样本级 interleave，同时**把生成和验证解耦**——rollout 写入队列，verifier 池异步消费，训练步从「已验证完成」的缓冲区取数据。这样慢 verifier 只增加端到端延迟，不阻塞每步。代价是引入了轻微的 off-policy 滞后（缓冲区里的样本来自上一两个 checkpoint），需要作为一个显式参数控制（缓冲深度 ↔ off-policy 程度的取舍）。

**一句话**：interleaved batching 的动机不是「多样性好听」，是**归一化统计量的可比性**。GRPO 的 advantage 在组内归一，但 batch 级的 loss 归一、梯度裁剪、优化器状态都是跨组共享的——域同质 batch 会让这些共享量在域之间来回跳。

## 12. 迭代闭环：训练 → trace → 失败模式 → 改数据 ⭐⭐⭐

```text
                 ┌──────────────────────────────────────────────┐
                 │                                              │
   数据 pipeline ─┴─→ 训练 run ─→ 训练动态指标 ─→ 下游 eval       │
   （§5–§8）           │            (熵/长度/          │         │
                       │             有效梯度率)       │         │
                       ↓                              ↓         │
                  分层 trace 抽样 (§10.2) ────→ 失败模式归类 ────┘
                                                  │
                    ┌─────────────────────────────┼──────────────────────┐
                    ↓                             ↓                      ↓
            改 verifier（§9）            改质量 gate（§5.3）      改难度带/配比（§7,§11）
            例：加严位置匹配              例：加「无矛盾」检查       例：抬高难度桶下限
```

**什么样的观察值得回流成 pipeline 改动**（不是每个 bug 都值得）：

| 观察 | 回流成什么 | 判据 |
|---|---|---|
| 一类 hack 在 >1% 的高 reward trace 里出现 | verifier 规则 + 一条离线检测指标 | 频率够高且可自动检测 |
| 某个数据源的 trace 大量格式错乱 | S0 解析器修复 + 该源整批重跑 | 源级问题，不是样本级 |
| 某题族稳定诱发失控推理 | 质量 gate 加一条题型排除 | 能刻画成规则 |
| 某个 checkpoint 后有效梯度率跌破阈值 | 触发 reserve 池重探（§7.4） | 自动触发，不需要人判断 |
| 单条题判错 | **不回流**，直接修那条 | 一次性问题做成规则会过拟合 |

**节奏建议**（可以直接讲的运营方案）：数据版本按周切；每个训练 run 结束做一次固定格式的失败模式归类（类别 + 频率 + 是否可自动检测 + 修法）；每个季度做一次全量重探 + 全量去污重跑。

> **和 [08](08_evaluation_production.md) 的关系**：那边讲的是产品系统的 offline→online 闭环，这里的闭环没有「线上」这一端——**裁判是下游 eval，反馈延迟是一个训练 run 的长度（几天）**，不是用户行为的几天。所以这里的闭环设计重点是**在一个 run 内部就能拿到的领先指标**（熵、长度、有效梯度率），否则你一次只能做一个实验。

## 13. 基础设施约束 ⭐⭐（我的真实经历）

### 13.1 先算一笔账：这条 pipeline 有多贵

```
一次难度探测覆盖 10,000 个候选题：
  10,000 × 16 条 × 平均 4,000 token = 6.4e8 token（探测）
正式 rollout（保留 8,500 条）：
  8,500 × 128 条 × 平均 8,000 token = 8.7e9 token（生成）
                                    ≈ 90 亿 token，一轮
```

> **这个数字要在面试里说出来**：一轮 rollout 生成的 token 量级和一次小规模预训练的数据量相当——区别在于它是 **decode**（访存受限、batch 效率差），不是 training。所以「RL 数据 pipeline」在工程上首先是一个**大规模批量推理系统**，数据清洗的 CPU 部分反而是零头。任何不谈吞吐的 RL 数据方案都是纸上谈兵。

### 13.2 共享集群与抢占（我自建的框架）

**现实约束**：GPU 是共享池，被其他团队抢占是常态，不是异常。

我做的事：

| 机制 | 做法 | 为什么这么设计 |
|---|---|---|
| **pause / resume** | 工作单元 = `(prompt_id, sample_idx)`；结果 append-only 写出并带幂等键；resume = 「diff 出还没完成的单元」 | 抢占可能发生在任意时刻，**checkpoint 粒度必须细到单条请求**，否则一次抢占损失整批 |
| **动态申领 / 让出** | 监控集群空闲容量，有空就扩，收到让出信号就优雅收缩（停止派新单元、等在途完成、写出、释放） | 抢占式作业的正确姿态是「把自己变成可被打断的」，而不是抢固定配额 |
| **TCP 式自适应并发（AIMD）** | 成功则**加性增加**并发；在一个**失败窗口**内则**乘性退避**；设并发下限 | 真正的瓶颈（KV cache 占用、调度队列、其他团队的负载）**不可直接观测**，唯一的反馈是错误率和延迟——这和 TCP 拥塞控制是同一个问题结构 |

**两个调出来的细节**（讲这种细节最能证明是真做过）：

1. **必须用失败*窗口*率，不能对单次错误退避**。共享集群上瞬时错误是常态，单次退避会让并发一路塌到底、吞吐归零。
2. **必须有并发下限**，否则连续退避后再也爬不回来（加性增加从很低的基数起步太慢，而下一次错误又会把它打回去）。

### 13.3 可恢复性与幂等：缓存键要包含什么

```
cache_key = hash(prompt_id, sample_idx, model_version,
                 sampling_params, prompt_template_version, verifier_version)
```

**最经典的 bug**：改了 prompt 模板但没改缓存键，于是复用了旧模板生成的 rollout，难度标注和实际训练分布对不上，而且**完全没有报错**。所有影响输出分布的东西都必须进键。

**另外要记录**：随机种子、后端版本（vLLM/SGLang 版本会改变采样实现）、以及**探测和正式 rollout 是否用了同一个后端**。

### 13.4 故障模式速查

| 故障 | 症状 | 对策 |
|---|---|---|
| 抢占 | 作业中断 | 细粒度 checkpoint + 幂等重放 |
| 慢节点 / 长尾请求 | p99 极长，整批卡住 | 请求级超时 + 重派（注意重派要保持幂等键） |
| verifier sandbox 逃逸/挂死 | 代码题卡住 | 硬超时、资源上限、网络隔离 |
| 后端 OOM（长 CoT 撑爆 KV cache） | 批量失败 | 按长度分桶调度；AIMD 退避 |
| 静默数据损坏 | 下游 p̂ 分布突变 | 每批次的分布指纹校验（长度分布、pass rate 分布）与上批对比 |

## 14. 常见失败模式：这个系统最容易在哪坏掉 ⭐⭐⭐

按「我实际会先怀疑什么」排序：

| # | 症状 | 最可能的根因 | 诊断 |
|---|---|---|---|
| 1 | **训练 pass rate 上翘但下游 eval 不动** | verifier 假阳性被找到（§9.4） | 抽 reward 最高的 trace 人工看；比对隐藏测试 vs 公开测试 |
| 2 | **训到中期梯度「消失」，loss 平了** | 难度漂移，池子整体变简单（§7.4） | 看有效梯度产出率和 p̂ 分布的众数 |
| 3 | 有效梯度率崩了但 p̂ 分布健康 | **熵坍缩**，不是数据问题（§7.1） | 看策略熵 + 组内答案唯一值个数；改 KL/温度/lr，别去改数据 |
| 4 | 平均长度翻倍但准确率平 | 失控推理或格式化推理（§10.1） | CoT 消融实验；truncation 率 |
| 5 | 难度标注和实际训练表现系统性偏差 | **探测与训练的采样参数不一致**（尤其 `max_tokens`） | 校验 schema 里的 sampling 字段 |
| 6 | 某个题族占据 batch 的大比例 | 去重不足，尤其缺解法骨架去重（§8.2） | 按解法簇统计 batch 组成 |
| 7 | 换了一版 judge 之后所有难度标注不可比 | verifier 未版本化 | `verifier.version` 进缓存键，换版即重探 |
| 8 | 好题莫名其妙变少 | **污染导致 p̂→1 被当简单题静默丢弃**（§8.3） | 去污前置 + 记录删除原因 |
| 9 | 模型在简单题上退化 | curriculum 升得太快，没有保留低难度锚点 | 难度桶比例里保留 [0.8, 0.95] 的一小部分 |
| 10 | 合成数据加了很多但没提升 | 多样性坍缩（种子太少） | 语义聚类看有效簇数，而不是看条数 |
| 11 | 每步耗时忽长忽短，GPU 利用率锯齿 | 域同质 batch + 慢 verifier 阻塞（§11.2） | 生成/验证解耦，异步缓冲 |
| 12 | 重跑同一个实验结果对不上 | 缓存键缺字段 / 未记种子（§13.3） | 补齐 lineage |

## 15. 10 分钟口述稿 ⭐⭐⭐

> **（澄清，1 分钟）** 我先确认四件事：训的是哪个 checkpoint、用什么 RL 算法和多大的组、目标是单域还是多域、以及数据生成和训练是不是共用同一批 GPU。最后一条最容易被忽略——**筛选本身就是 rollout，它是从训练预算里扣的**。
>
> **（定位，1 分钟）** 我要强调一个和 SFT 数据的根本区别：这条 pipeline 的产出物不是「问题 + 标准答案」，是**一组带 verifier 的 prompt，且每条对当前策略而言处在有梯度信号的难度带里**。在 SFT 里「好答案」是资产，在 RL 里它只能存在于 verifier 一侧——泄漏到 prompt 里的答案会让这道题 pass rate 变成 1，然后被我的难度筛选静默删掉。
>
> **（指标，1 分钟）** 所以我汇报的不是「造了多少条」。我报**有效梯度产出率**——一个 batch 里既不全对也不全错的组占多少。它能直接换算成钱：如果是 60%，说明 40% 的 rollout 预算生成的 token，advantage 恒等于 0。最终裁判还是固定算力下的下游 eval 提升，但那个反馈要几天，所以中间要靠有效梯度率、策略熵、平均长度这三个领先指标。
>
> **（供给，1.5 分钟）** Prompt 有四条供给线：开源集（已被榨干且是污染重灾区，只当 baseline）、**原始语料转换（这是真正的产能，也是我在 Reflection 的主线）**、合成（用来定向填难度空洞，不做主力，因为种子少会多样性坍缩）、真实用户分布（量少但用来定义合成往哪儿靠）。原始语料那条线我做的是一个多阶段 LLM 流水线：解析 → 抽题 → question rewriting 做成自包含题面并剥离答案 → answer rewriting 从散落讨论里归纳唯一答案 → QA 转换。质量特征我打的标是：自包含、无矛盾信息、假设是否给足、答案唯一、无泄漏。**「无矛盾」这条对 RL 特别关键**——矛盾题在 SFT 里只是噪声，在 RL 里它的 pass rate 会稳定在一个低值，**恰好落进我的难度保留带**，被当成好难题大量 rollout。所以质量 gate 必须在难度探测之前。
>
> **（可验证化，1 分钟）** 能往规则/符号等价/单元测试/形式化走就绝不停在整体 judge，理由后面讲。转换有三条路：答案抽取加类型化比较器、单元测试化、把证明降级成可数值化的推论。第三条有代价——降级会改变难度，**转完必须重新探测**。实在不可验证的用 claim 级 rubric，把整体打分拆成 N 个独立的 yes/no。这个我有实测支撑：在一个医疗任务上，整体相似度指标预测「不安全回复」的 AUROC 只有 0.569，拆成 claim 级 grounding 之后到 0.844，置信区间不重叠。**判断迁移过来就是：judge 不一致往往不是模型笨，是我们让它一次做了太多判断。**
>
> **（难度筛选，2.5 分钟——最重的一段）** GRPO 里一个 prompt 全对或全错，组内优势严格为 0，但照样消耗 G 条 rollout。**如果池子平均 p 是 0.9、G 是 8，那 43% 的 rollout 算力生成的 token 对应的 advantage 恒等于零。** 我的做法是两阶段：正式 rollout 之前先用 **16 条**探测，全对全错的直接丢，保留的再跑 **128 条**，**大约 12% 算力花在筛选上**。16 这个数字是算过的：以「全对或全错」为判据，真实 p 在 0.2 到 0.8 之间的题误杀率不到 3%，但 p 超过 0.95 的能捞掉四成以上——它不是一个精确的 p 估计器，**我也不需要精确估计 p，我只需要区分退化和不退化**。这个思想和 DAPO 的 dynamic sampling 是一致的，区别是它在训练循环里做、永远贴合当前策略但每步耗时可变且不可复用；我在离线做、便宜可抢占可复用但会过期。**我的答案是叠加：离线粗筛干掉「对任何近期 checkpoint 都退化」的大头，在线细筛处理漂移的残差。**
>
> 然后是漂移：**难度不是题目的属性，是题目、策略、采样参数的联合属性**。策略变强，整个池子的 p 向右漂，训到中期梯度就没了。所以阈值必须自适应——训练本身的 rollout 就在免费提供每道题的当前 pass rate，用它维护滑动估计；平均 p 越过上界就触发对 reserve 池的重探。**早期判为「全错」的题绝对不能删，要进 reserve**，它们正是几千步之后的燃料。
>
> **最后一个关键区分**：组内优势为 0 有两个来源——题目退化和熵坍缩。筛数据只能解决第一个。所以我同时监控策略熵和组内答案的唯一值个数，避免把优化问题误诊成数据问题。
>
> **（reward 与 hacking，1.5 分钟）** verifier 的两类错误代价严重不对称：假阴性只是噪声，假阳性会被策略**主动搜索**——RL 的机制就是找高 reward 路径，而假阳性区域是免费高分。所以我对「判对」这一侧要求高 precision，**匹配要严格、等价要宽松**。搞反了就是最经典的 hack：宽松匹配加严格等价，模型学会枚举一串候选答案，只要正确答案在里面就通过，而 pass rate 曲线看起来完全正常。
>
> 检测靠读 trace，这是唯一能发现我没预料到的失败模式的通道。我实际见过四种：格式化推理（推理有外形没做功，用 CoT 消融验证——截断推理强制作答，准确率不掉就是它）、失控推理（撞 max_tokens，注意不要对截断一刀切给 0，那是噪声惩罚）、错误推理侥幸答对（小答案空间的题天然高危）、答案泄漏。读 trace 我是分层抽样加固定节奏：最高 reward 的、组内方差最大的、pass rate 跨 checkpoint 突然从 0 跳到 1 的（这是假阳性被发现的瞬间，最强的 hack 信号）、长度 p99 的、新数据源的。
>
> **（基础设施，1 分钟）** 一轮 10000 题的探测加 rollout 大概要生成 **90 亿 token**——和一次小规模预训练的数据量同量级，而且是 decode 不是 training。所以这首先是一个批量推理系统。我们的卡是共享池，被抢占是常态，我自建了 pause/resume 框架：工作单元细到 (prompt_id, sample_idx)，结果 append-only 带幂等键，resume 就是 diff；动态申领和让出容量；并发用 **TCP 式的 AIMD** 调节——成功加性增加，失败窗口内乘性退避。这里有两个调出来的细节：**必须用失败窗口率而不是单次错误退避**，否则瞬时错误会把并发打到零；**必须有并发下限**，否则退避之后爬不回来。
>
> **（闭环，30 秒）** 整个东西是个环：训练 → 读 trace → 归类失败模式 → 回改 verifier、质量 gate 或难度带。我会区分哪些观察值得回流——一类 hack 出现在超过 1% 的高分 trace 里才做成规则，单条题判错就直接修那条，不做成规则。

## 16. 面试前一页速记

**一句话主张**：产出物不是「好答案」，是**带 verifier 且对当前策略有梯度信号的 prompt**。

**SFT vs RL 数据**：SFT 里好答案是资产，RL 里好答案是风险（泄漏 → pass rate=1 → 被静默丢弃）。

**核心公式**：`A_i = (r_i − mean(r))/std(r)` → 全对/全错 ⇒ 分子为 0 ⇒ **梯度严格为 0，但算力照付**。

**退化率表**（`p^G + (1−p)^G`）：G=8 时，p=0.9 → **43% 退化**；p=0.95 → 66%。G=16 时 p=0.9 → 18.5%。

**⭐ 优势为 0 的两个来源**：题目退化（数据侧，可筛）／**熵坍缩（优化侧，筛数据没用）**。

**两阶段探测**：16 条探测 → 丢全对全错 → 128 条正式，**约 12% 算力**。误杀率：p∈[0.2,0.8] <3%，p=0.95 → 44% 被丢。**它不是 p 估计器，是退化判别器。**

**筛选占比公式**：`16/(16+128k)`；k=0.85 → 12.8%（是质量闸门，不省钱）；k=0.4 → 23.8%（省一半算力）。

**vs DAPO dynamic sampling**：同一思想。在线=贴合当前策略但每步耗时可变、不可复用；离线=便宜可抢占可复用但会过期。**答案是叠加。**

**漂移**：难度 = (题, 策略, 采样参数) 的联合属性。**too_hard 进 reserve 池不许删**，平均 p 越界触发重探。目标带 [0.2, 0.8]，众数 0.4–0.6。

**可验证性谱系**：精确匹配 < 符号等价 < 执行验证 < 形式化 < claim 级 rubric < 整体 judge。**能下沉就下沉。**

**verifier 两类错误**：假阴性=噪声，策略不会去撞；**假阳性被策略主动搜索，危害随时间增长**。⇒ **positive label 上 precision-first**。

**匹配严格、等价宽松**。反过来 ⇒ 模型枚举候选答案通关。

**judge 不一致的根因**：作用域太大。缩小作用域 > 拆 claim 级 > few-shot 锚例 > 多 judge 投票（最后才用）。实测支撑：整体相似度 AUROC 0.569 → claim 级 0.844。

**四种 hack**：格式化推理（CoT 消融验证）／失控推理（别对截断一刀切给 0）／错误推理侥幸对（小答案空间高危）／答案泄漏（no-CoT 探针，8 token 全量跑）。

**读 trace 分层**：最高 reward / 组内方差最大 / **pass rate 从 0 跳到 1** / 长度 p99 / 新数据源 / eval 回归。

**去重四层**：exact → near → semantic → **解法骨架**（RL 特有；探测的 16 条 rollout 顺手复用，边际成本≈0）。

**污染的反直觉后果**：污染 ⇒ p̂→1 ⇒ **好题被难度筛选静默删掉**。所以去污必须前置且记录删除原因。

**配比**：比例下限保底 + 学习进度分配剩余 + **冻结配比的 canary 做对照**。

**Interleaved batching 的真实理由**：不是「多样性好听」，是**归一化统计量跨步可比**。慢 verifier 用异步缓冲解耦，代价是轻微 off-policy。

**算力量级**：1 万题 × (16 探测 + 128 正式) ≈ **90 亿生成 token**，和小规模预训练同量级，但是 decode。

**基础设施三件套**：请求级 checkpoint + 幂等键 → pause/resume；动态申领让出；**AIMD 并发（失败窗口率退避 + 并发下限）**。

**缓存键必须含**：prompt_id、sample_idx、model_version、sampling_params、prompt_template_version、verifier_version。

## 17. 常见追问 + 应答要点

1. **「为什么不干脆全都在训练循环里做 dynamic sampling？」**
   → 因为我会为「对任何近期 checkpoint 都退化」的那批题反复付 rollout 费用，且每个实验重付一遍。而且在线过滤让每步耗时可变，分布式下同步开销明显。离线负责大头（可复用、可抢占、可错峰），在线负责漂移残差。

2. **「16 条探测的统计功效够吗？」**
   → 如果目标是估计 p，不够（SE≈0.12）。但我的判据不是估 p，是**判别退化**——`p^16+(1−p)^16` 在 p∈[0.2,0.8] 上小于 3%，在 p>0.95 上大于 44%。这个判据恰好在我需要它敏感的地方敏感。要更精细的 curriculum 分桶才需要更大的 n，那时我会按域设不同的 n_probe。

3. **「模型变强之后数据不就没用了吗？」**
   → 对，这正是要点。所以①难度标注绑 checkpoint 并会 stale；②too_hard 池必须保留、定期回捞；③训练本身的 rollout 免费提供当前 p̂，不用额外探测；④长期看供给侧必须持续产出更难的题，否则 RL 会撞天花板——这是「合成能不能超过教师」的问题，也是我认为原始语料转换比合成更有战略价值的原因。

4. **「怎么证明你这批数据真的有用？」**
   → 固定算力的 A/B：同一 checkpoint、同一超参、同样的总 rollout 预算，加这批 vs 不加，比下游 eval。**不能用「训练 pass rate 涨了」证明**，那可能是难度筛松了或者 verifier 被 hack 了。方法论同 [07 §13](07_pretraining_data.md) 的 data ablation ladder。

5. **「verifier 假阳性怎么主动找，而不是等它出问题？」**
   → 三条：①对 reward=满分的样本做**分层人工抽检**，报假阳性率作为 guardrail 指标；②准备一批**对抗样本**（枚举式答案、hard-code 的代码解、格式合规但内容空洞的回答），当作 verifier 的单元测试，每次改 verifier 跑一遍；③监控「pass rate 跨 checkpoint 突然跳变」的 prompt。

6. **「judge 一致性差，多 judge 投票不就行了？」**
   → 投票是最后手段。它成本翻倍，而且**共享盲区不会被投票消除**——三个同源模型会在同一个地方一起错。我优先缩小 judge 的作用域：能抽答案就别让它读全文，能拆 claim 就别让它整体打分。我有对照数据支持这个排序（0.569 → 0.844）。

7. **「多域混合，怎么防止模型只在最容易验证的域上变强？」**
   → 三点：①配比设**比例下限**，不让 yield 驱动的机制饿死难验证的域；②eval 必须**分域报**，总均值会掩盖；③警惕 yield 驱动的自我强化——可验证性和产出量正相关，任性地按产出配比会一路滑向数学。

8. **「合成数据能不能超过教师模型的水平？」**
   → 单纯蒸馏式合成不能，天花板就是教师。能超过的路径是：①**逆向构造**（先造答案/结构再造题，难度不受教师解题能力限制）；②**组合难化**（把多个已验证的子问题组合，验证器仍然可靠）；③**从人类语料挖**（竞赛题、研究性问题的难度上界是人类，不是教师）——这也是我把原始语料转换当主线的原因。

9. **「不可验证的领域怎么办？这套还成立吗？」**
   → 核心机制（探测难度、丢退化样本）依赖的是「reward 有区分度」，不依赖「reward 可程序化」。judge-based reward 同样可以做组内方差探测。但**假阳性风险高一个量级**，所以我会：把难度带收窄（更保守）、增加人工抽检比例、并且优先做 §6 的可验证化改造，而不是直接上 judge。

10. **「RL 之前需要 SFT 吗？数据 pipeline 要不要顺便产 SFT 数据？」**
    → 需要，但用途不同：SFT 负责把格式、工具协议、基本行为教会，让策略在 RL 的探索空间里有一个非零起点。如果基座连答案格式都不稳，所有题的 p 都接近 0，整个难度筛选机制会失效（全部落进 too_hard）。**顺便产 SFT 数据是可以的**——被丢弃的「太简单」样本加上它们的正确 rollout，正好是高质量 SFT/rejection-sampling 语料。这是一个很自然的副产品回收。

11. **「怎么处理部分正确（partial credit）？二元 reward 是不是太粗？」**
    → 连续 reward 让组内方差更容易非零，看起来能缓解退化问题，但它把假阳性风险变成了连续谱——「答对一半」的判定比「对/错」更依赖 judge，更容易被 hack。我的取向是：**能二元就二元，需要 partial credit 时用可程序化的分解**（比如代码题按测试用例通过数），而不是让 judge 给 0–1 的连续分。

12. **「探测的 rollout 能不能顺便用作训练数据？」**
    → 探测的 16 条是 on-policy 的，理论上可以进训练 batch，但要小心：①它们来自探测时的 checkpoint，训练开始后就 off-policy 了，需要重要性修正或严格限制滞后；②被丢弃的样本的 rollout 不能进（那些组的 advantage 是 0，进去只是稀释 batch）。**更有价值的复用是拿它们做解法骨架去重（§8.2）和 SFT 语料回收**，那两个用途没有 on-policy 要求。

13. **「如果只给你一周，先做什么？」**
    → 先做**难度探测**这一件事，接在现有的开源数据集后面。理由：它不需要新的数据供给、不需要新的 verifier，改动最小，但能立刻给出「我现在有多少算力在空转」这个数字——有了这个数字，后面所有投资（改供给、改 verifier、改配比）才有 ROI 论证的分母。

## 19. 诚实边界：哪些要主动标注

| 边界 | 怎么诚实地说 |
|---|---|
| **RL 训练器内部**（PPO/GRPO 的分布式实现、rollout 调度器、优化器细节）不是我主责 | 「训练器本身不是我的模块——我在 mid-training 侧负责数据供给和筛选，以及它依赖的批量推理基础设施。算法层面我能讲清楚为什么退化样本梯度为 0、以及 DAPO 那几个改动在解决什么，但我没有实现过分布式 rollout 调度器。」 |
| **没有金融/交易经验** | 直接说没有，然后转到结构：「金融我完全没做过。如果这里的任务是把交易信号做成可验证 reward，我能讲的是**怎么判断一个 reward 是不是被策略主动搜索**这类结构问题，具体的市场微结构我需要学。」 |
| **没有大规模在线 serving 的 oncall 经验** | 「我做的批量推理是离线吞吐场景——抢占、幂等、可恢复、并发调节这些我踩过；但**面向用户的低延迟在线 serving 和 oncall 我没做过**，p99 SLO、限流降级、事故响应那套我只有读来的知识。」（这条在被问「训完怎么上线」时一定要说） |
| **多轮/agentic RL 环境的数据** 我做的主要是单轮可验证的 math/STEM | 「我的经验集中在单轮、终态可验证的题。多轮 agentic RL 的环境构建、中间状态的 credit assignment 是相邻但不同的问题，我能推理但没有实操过。」 |
| **真实用户 prompt 分布** 接触有限 | 「mid-training 侧我拿到的主要是语料和合成的 prompt，产品侧真实分布我接触有限——所以 §5.1 里那一条我讲的是设计考量，不是我做过的。」 |
| **HCI 博士背景** | 不用回避，它是资产：「我的 HCI 训练让我对『我以为我在测的东西其实不是』这类 construct validity 问题特别敏感——§10 那套读 trace 的分层协议本质上就是定性编码的方法。」（迁移句式见 [12](12_personal_bridge.md) §3） |

**绝不要说的**：把设计方案说成已做过的结果；把团队产出说成个人 ownership；报一个自己没算过的数字。本篇里所有带具体数字的地方，要么是真实经历（16/128/12%），要么是当场可推导的（退化率表、筛选占比公式、90 亿 token），后者要说清楚是「我现在算给你看」。
